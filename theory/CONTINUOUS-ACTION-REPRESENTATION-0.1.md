# 连续行动结构表示 v0.1

- 英文简称：Continuous Action Structural Representation 0.1
- 机器简称：`CA-SR 0.1`
- 状态：连续行动先行组的冻结受测伴随表示
- 日期：2026-07-27
- 来源：[CA-01 核心命题](../research/continuous-action-pilot-ca-01.md)、[CA-02 案例职责架构](../research/continuous-action-pilot-ca-02-case-roles.md)与 [GP-SR 0.1](STRUCTURAL-REPRESENTATION-0.1.md)

## 1. 用途与边界

CA-SR 0.1 为第二轮**连续行动与具身控制组**保存可复算的运行边界与轨迹证据。它回答：

> 在输入识别到效果提交之间，如果存在规则可查询、可独立改变且会改变轨迹或结果的中间边界，当前项目能否把这些边界忠实编码，并让独立执行者重构和预测？

CA-SR 0.1 是 GP-SR 0.1 的测试伴随表示，不是：

- GP-SR 0.2；
- 完整游戏描述语言或可执行 DSL；
- “原语 → 机制 → 玩法模板 → 游戏”之间的新层级；
- 对“连续动作原语”或其他新**原语**的预先接受；
- 玩家技能、难度、平衡、策略或体验的证据。

本版本只为连续行动方法试验冻结。若来源事实清楚而本表示不能承载，必须登记 `representation_gap`；不得为了让测试通过而在运行中增加字段。

## 2. 与 GP-SR 0.1 的关系

CA-SR 0.1 继续使用 GP-SR 0.1 的：

- 基础引用类型；
- 十一项**规则槽位**；
- 八种机制组合关系；
- `encoded`、`source_underdetermined`、`representation_gap` 与 `scope_excluded`；
- 说明区不得偷藏规则事实的纪律；
- 冻结后只能用新版本修改的版本纪律。

本版本只增加测试局部记录：

- 多种**时间基准**；
- 信号到**输入**、**规则动作**与具体动作实例的识别路径；
- 案例特定的动作生命周期及权限变化；
- **过程**更新、状态通道与轨迹；
- 候选发生到正式**事件**、**结算**与**效果**的裁定路径；
- **语义反馈**对指定观察者何时可得；
- 输入识别、动作许可、结算、实际效果与系统评价的分层结果；
- 可机械生成的完整视图、角色视图与压缩负对照。

这些记录是对既有类型、槽位和关系的结构化观察，不因获得字段而自动成为**原语**。

## 3. 单一事实源与生成视图

每个案例只维护一份规范事实源：

```text
canonical source encoding
├── audit view
├── blind rich view
├── CA-R1 / CA-R2 / CA-R3 / CA-R4 view
└── atomic projection
```

其中：

- `audit view` 保留作品身份、版本、来源定位、实现层和审核异议；
- `blind rich view` 隐去身份，但保留本轮允许的完整结构；
- 角色视图只保留该角色事前声明需要的字段；
- `atomic projection` 是删除中间边界后的压缩负对照。

角色视图与压缩视图必须由规范事实源按版本化白名单机械生成，不得手写。原始轨迹单独保存，以 ID、版本和 SHA-256 引用；派生轨迹还须记录派生算法版本与输入散列。

顶层最小结构：

```json
{
  "representation_version": "CA-SR 0.1",
  "artifact_version": "0.1.0",
  "case_scope": {},
  "references": [],
  "rules": [],
  "time_bases": [],
  "state_channels": [],
  "operational_records": [],
  "composition_edges": [],
  "temporal_edges": [],
  "operational_edges": [],
  "trace_contract": {},
  "source_issues": []
}
```

数组次序只负责稳定序列化，不表示时间、因果、优先级或生命周期转移。

## 4. 来源事实状态

所有会影响重构或预测的字段使用同一事实包装：

```json
{
  "status": "encoded",
  "value": {},
  "provenance_refs": ["src-01"]
}
```

允许值和约束：

| 状态 | 使用条件 | 不允许的做法 |
| --- | --- | --- |
| `encoded` | 来源、夹具或测量能确定该值 | 缺少定位；把猜测写成确定值 |
| `source_underdetermined` | 冻结来源不足、互相冲突或无法确定 | 用平台默认值、零或空数组代替未知 |
| `representation_gap` | 来源事实清楚，但当前类型、槽位或关系无法承载 | 用说明、字段名或不透明参数偷渡 |
| `scope_excluded` | 该事实已在测试前明确排除 | 排除一项硬条件必需事实 |
| `not_applicable` | 某条件字段在本案例中确实没有语义对象 | 用于掩盖未知或省略必填记录 |

`not_applicable` 只适用于条件字段，不替代四种 GP-SR 来源编码状态。

规则来源继续区分规范文本、软件或物质制品实装、裁定或程序执行，以及游玩实例观察。项目夹具、仪器测量和派生计算只标为证据角色，不冒充来源规则。不同实现层冲突时，各层事实分别编码，合并判断保持 `source_underdetermined` 并互相引用。

## 5. 记录类型

### 5.1 `reference`

引用记录声明一个对象在本案中的语义职责：

- ID；
- GP-SR 基础类型；
- 测试本地职责；
- 去身份描述；
- 审计视图中的来源名称与身份定位。

允许的测试本地职责包括 `input`、`rule_action`、`action_instance`、`event`、`process`、`resolution`、`effect` 和 `feedback_observation`。这些机器判别值只帮助 Schema 检查，不改变其理论地位。

### 5.2 `rule_frame`

每条规则继续使用 GP-SR 的十一项**规则槽位**。每个槽位都必须携带来源事实状态。自动系统过程没有代理时，`actor` 可以是系统引用，也可以在来源确实没有对应职责时标为 `not_applicable`；不能为满足自然语言句式虚构行动者。

### 5.3 `time_base`

每种会改变先后、许可或轨迹解释的时钟分别记录：

- 所有者；
- 推进条件；
- 坐标类型；
- 排序规则；
- 单位；
- 固定或可变步长；
- 暂停、积压、快照与阶段顺序；
- 与其他时间基准的已知映射或未知关系。

渲染帧、模拟更新、输入采样、规则帧、音频时钟和墙钟不得默认等同。

### 5.4 `state_channel`

状态通道记录：

- 值类型；
- 所指**状态**或**关系**；
- 读取者与写入者；
- 单位、坐标系和数值精度；
- 等价容差；
- 快照与提交边界；
- 初始值和停止边界所需值。

“速度为 3”不合格；必须说明单位、坐标系、时间基准和精度。

### 5.5 `input_action_path`

输入路径至少记录：

- 信号或输入通道；
- 采样的**时间基准**；
- 边沿、保留、缓冲、过期与消费规则；
- 从信号到**输入**的识别规则；
- 从**输入**到**规则动作**的映射；
- **动作合法性**检查；
- **行动实现载体**与受控实体；
- 输出动作或拒绝结果。

输入到达、被采样、被识别、被映射和取得动作许可是可分别编码的边界，不因时间接近而自动合并。

### 5.6 `action_lifecycle`

动作生命周期记录：

- 所属**动作**与具体动作实例；
- 入口和退出；
- 来源明确的里程碑；
- 里程碑之间的显式转移；
- 撤回、替换、修正和取消权限怎样变化；
- 成本、响应窗口和可见性怎样变化；
- 与相关**过程**、候选发生和效果的接口。

本版本不预设“启动—有效—恢复”等万能阶段枚举。某个里程碑是否构成**锁定点**，必须由许可、成本或可逆性的实际变化推导；不得只填 `is_lock_point: true`。

### 5.7 `process_profile`

过程记录至少包含：

- **过程**身份与活动作用域；
- 调度的**时间基准**；
- 每次更新读取和写回的状态通道；
- 更新规则；
- 运行中的输入是否调制同一过程；
- 暂停、积压与终止；
- 首个候选发生的输出边界。

若中途输入形成新动作、取消或替换当前动作，应编码为动作关系；只有输入改变同一过程的参数或轨迹时才使用 `modulates`。

### 5.8 `adjudication_path`

裁定路径记录：

- 候选发生；
- 检测、分类、重检和优先级阶段；
- 每一阶段的显式转移；
- 具备裁定资格的系统角色；
- 正式**事件**；
- **结算**；
- **效果**提交；
- 复核、撤销或重启条件。

接触测量、阈值越过或日志回调不能自动成为正式事件；必须通过来源支持的裁定关系。

### 5.9 `feedback_contract`

反馈记录指定：

- 观察者；
- 被观察的来源事实、事件、结算或效果；
- 信息内容；
- 可得时点；
- 准确性、延迟、保留和撤回；
- 呈现载体；
- 被信息门控的后续响应机会。

世界事实存在、效果已经提交和参与者已经取得可用信息是不同判断。

### 5.10 `outcome_frame`

结果框分别记录：

1. 输入是否被识别；
2. 对应动作是否合法并被实例化；
3. 候选发生怎样被**结算**；
4. 实际**效果**是否提交；
5. 系统如何更新目标、得分或其他评价。

玩家个人评价和实际体验在本轮默认为 `scope_excluded`。

## 6. 有类型关系

禁止使用一个无类型 `relation` 字段。关系分为四族：

### 6.1 GP-SR 组合关系

```text
sequence
parallel
nesting
gating
feedback
mutual_exclusion
conversion
coupling
```

### 6.2 时间关系

```text
before
simultaneous_with
overlaps
during
at_next_opportunity_of
```

### 6.3 运行关系

```text
samples
recognizes_as
maps_to
instantiates
scheduled_by
reads
writes
modulates
transitions_to
cancels
replaces
```

### 6.4 裁定与观察关系

```text
detects
rechecks
adjudicates_as
resolves_to
commits
exposes_to
gates
```

每条边至少包含：

```json
{
  "edge_id": "edge-001",
  "kind": "recognizes_as",
  "from_id": "input-01",
  "to_id": "rule-action-01",
  "condition_ids": ["condition-01"],
  "scope_ids": ["scope-01"],
  "source_fact": {}
}
```

源码调用顺序、动画帧编号和 JSON 数组位置都不能替代显式关系。

## 7. 轨迹格式

日志中的基本项目称为 `trace_entry`，避免把所有记录都误称为规则上的**事件**：

```json
{
  "trace_entry_id": "te-000042",
  "serialization_ordinal": 42,
  "kind": "lifecycle_milestone_reached",
  "subject_ids": ["action-instance-01", "milestone-02"],
  "time_marks": [
    {
      "time_base_id": "tb-simulation",
      "coordinate": {
        "numerator": "127",
        "denominator": "60"
      }
    }
  ],
  "structure_record_ids": ["lifecycle-01"],
  "payload": {},
  "provenance": {
    "kind": "instrument_measurement",
    "locator_id": "trace-source-01"
  }
}
```

允许的最小 `kind`：

```text
input_arrived
input_sampled
input_buffered
input_expired
input_recognized
action_legality_evaluated
lifecycle_milestone_reached
permission_changed
process_update
state_sampled
state_committed
candidate_occurrence
formal_event_recorded
resolution_completed
effect_committed
feedback_available
feedback_withdrawn
scope_started
scope_ended
```

轨迹必须遵守：

- 数值时间使用整数或有理数字符串，不使用不可复算的浮点时间；
- `serialization_ordinal` 只负责稳定排序，不证明因果或同时；
- 一个条目可以引用多个时间基准；
- 不知道精确时钟映射时，保留来源支持的相对时间关系；
- 来源记录、仪器测量和规则派生分别标明；
- 原始轨迹与派生轨迹分别保存；
- 每个派生项引用算法版本、输入散列和容差；
- 候选发生不得绕过裁定路径直接写为正式事件。

## 8. 三个核心角色的最低视图

### 8.1 `CA-R1` 识别—锁定入口

必须包含：

- 至少一个 `input_action_path`；
- 输入采样的 `time_base`；
- 识别、合法性和锁定相关规则；
- 至少一个 `action_lifecycle`；
- 输入到规则动作、规则动作到动作实例的关系；
- 输入到达、采样、识别、合法性、里程碑与权限变化轨迹；
- 一组跨越待测边界而其他条件相同的输入对照。

### 8.2 `CA-R2` 调制—轨迹运行

必须包含：

- 运行中的动作或过程身份；
- 至少一个 `process_profile`；
- 输入、位置、速度或其他过程状态的 `state_channel`；
- 调度时间基准、读取快照、更新与写回关系；
- 中途输入属于同一过程调制还是建立新动作的明确归属；
- 过程开始、输入采样、过程更新、状态写回和候选发生轨迹。

### 8.3 `CA-R3` 候选—裁定出口

必须包含：

- 至少一个 `adjudication_path`；
- 候选发生、正式事件、结算和效果引用；
- 裁定资格、重检或优先级的来源状态；
- 候选发生前保持相同的世界轨迹；
- 候选发生、分类或重检、正式事件、结算和效果提交轨迹；
- 至少一个 `outcome_frame`。

### 8.4 `CA-R4` 反馈—再进入闭环

只有 CA-02 的触发条件成立时加入，必须包含：

- 至少一个 `feedback_contract`；
- 指定观察者、信息内容与可得时间；
- 保持相同的世界轨迹和实际效果；
- 信息准确性、延迟、保留或撤回；
- 被反馈门控的后续响应机会；
- 效果提交、反馈可得或撤回及响应窗口轨迹。

整组仍须至少一个案例记录**行动实现载体**的实际作用，并至少一个案例闭合“效果或反馈 → 后续响应机会”。

## 9. 压缩负对照

`atomic_projection` 由完整表示机械生成，只保留：

- 不带结构暗示的动作 ID；
- 声明的初始状态投影及其已知值；
- 声明要观察的终止状态字段，不含本轮实际结果值；
- 允许的效果类型与输出通道，不含本轮实际结果值；
- 起止时间。

它明确删除：

- 输入采样、识别与保留；
- 生命周期里程碑和权限变化；
- 中间过程更新；
- 候选发生与正式事件的区别；
- 结算、效果提交与反馈可得的区别。

动作名称、参数名、ID 和说明不得出现“可中途修正”“延迟判定”“命中后取消”等答案信息。基线与变体使用相同动作 ID 和相同字段形状。

压缩视图从冻结的规则描述生成，不从已经执行出的变体结果反推。压缩视图不是故意制作的坏答案，而是 CA-01 中“原子动作加无类型状态变化是否足够”的最强公平实现。若它在不依赖专名、自由文本或不透明参数的情况下仍能唯一重构并正确预测，CA-01 必须在该案例上被判为受反驳。

变体预测另使用一个对两种视图字节相同的中性信封。信封只提供变量 ID、基线值、变体值、不变量 ID、允许输出字段和停止边界，不解释变量的因果职责。丰富视图可以通过正式关系引用该变量；压缩视图若已删除相关边界，就不能用带答案的参数名补回。这样测试的是表示是否保存了关系，而不是一方是否少收到变体通知。

## 10. 防偷渡规则

1. 禁止 `custom` 类型、任意关系和无 Schema 的 `parameters`。
2. 自由文本只能解释已经编码的结构；硬条件判断不得依赖只存在于说明中的事实。
3. 关键值必须带单位、坐标系、容差和来源。
4. 未知不得用零、空集合、当前帧或平台默认值代替。
5. 数组顺序不表示时间、因果、优先级或状态转移。
6. 函数、回调、动画帧或硬件采样只有在规则许可、正式事件、效果或信息可得性会读取该差异时，才可成为受测边界。
7. 轨迹精度、帧率和日志粒度本身不构成机制差异。
8. 预测、答案与运行结果不得写入来源编码。
9. 作品名、专有术语和原始来源定位只进入审计视图。
10. “更顺手”“更难”“更公平”“玩家会”等行为或体验判断不得进入结构结果。

## 11. 表示结果与核心命题分轴

本轮至少分别报告“CA-01 压缩命题”与“CA-SR 0.1 表示能力”：

| CA-01 压缩命题 | CA-SR 0.1 | 解释 |
| --- | --- | --- |
| 受支持 | 足够 | 压缩视图发生别名化；丰富视图可重构并正确预测 |
| 受反驳 | 足够，或更紧凑表示已经足够 | 压缩视图在不偷渡信息时仍能唯一重构并正确预测 |
| 受支持或结论不定 | `representation_gap` | 区别可能真实，但当前表示无法承载；不能宣称表示通过 |
| 结论不定 | 结论不定 | 来源、变量隔离、时钟映射或轨迹精度不足 |
| 任意 | 轮次无效 | 冻结、预测隔离或制品完整性失效 |

进一步约束：

- 明确来源事实无法编码时立即登记 `representation_gap`；
- `representation_gap` 不自动产生新**原语**，只触发轮后候选修订；
- 字段齐全但独立重构仍不能恢复必要边界，属于表示或模型失败；
- 来源没有说明采样、步长或裁定关系时属于来源不足，不改写为表示缺口；
- 不得用“更详细总是更好”挽救被压缩视图成功反驳的命题。

## 12. 版本纪律

CA-SR 0.1 一旦随正式轮次的 `frozen` 提交进入 Git，任何改变记录类型、关系、允许词汇、轨迹语义、事实状态或压缩投影的修订都必须发布新版本并进入新轮次。

Schema、生成器与文字规范的语义必须一致。若修订只改变格式但会改变测试者可见字节，同样不得覆盖已冻结输入。

本版本没有产生新的已接受**共享术语**，因此不修改项目词表或公开理论主链。
