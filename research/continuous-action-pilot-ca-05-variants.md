## 1. 共同实验纪律

每个核心角色只允许一个预先命名的逻辑变量：

```text
冻结基线
+
一个逻辑变量
+
保持不变项
+
事前结构预测
+
可复算结果
```

“单变量”不等于补丁只能改一行。若一个因果关系需要测试接缝、状态字段和日志共同实现，可以有多行补丁，但所有改动必须分别归入：

1. 非语义兼容；
2. 观察仪器；
3. 唯一规则变体。

三类补丁分别保存和审核。任何第二项规则关系变化都会使该运行无效。

正式结果揭示前必须冻结：

- 基线与变体的完整制品身份；
- 初始状态；
- 原始输入轨迹；
- **时间基准**与停止边界；
- 隔离变量；
- 保持不变项；
- 预测文本及 SHA-256；
- 结果读取算法、容差和反驳条件。

本轮只预测结构状态、轨迹、正式结果和反馈可得性，不预测玩家技能、难度、偏好、策略或体验。

## 2. `CA-R1`：已缓存请求能否越过取消资格门

### 2.1 冻结基线

制品：

- *FOOTSIES* 标签 `1.5.0`；
- 提交 `7eaaad799bb7912625c15af9407c2c67e6305d75`；
- Unity `2018.1.1f1`；
- F00；
- 固定步长 `0.02 s`。

初始状态：

- 当前动作为 `STAND`；
- 无硬直；
- 无缓存动作；
- 当前攻击命中计数为零；
- 对手固定在所有真实攻击框之外；
- AI、移动方向和其他输入关闭。

冻结输入以战斗固定更新为单位：

| 更新 | 输入 | 更新后必须观察到 |
| ---: | --- | --- |
| `0` | 攻击按下 | 从 `STAND` 进入 `N_ATTACK` |
| `1` | 释放 | `N_ATTACK` 继续，动作帧进入取消缓存区间 |
| `2` | 再次按下 | 请求映射为 `N_SPECIAL`，待执行记录为 `110` |
| `3`–`6` | 中立 | 根据取消资格决定是否进入 `N_SPECIAL` |

更新编号是夹具坐标，不替代来源动作帧。彩排必须断言第二次按下实际在 `N_ATTACK` 的缓存帧内被处理；断言失败时不得移动输入后继续沿用本版本预测。

### 2.2 唯一变量

只修改 F00 数据中的：

```text
允许空振取消 =
  基线：否
  变体：是
```

对应来源字段为 `canCancelOnWhiff: 0 → 1`。来源中的取消表、动作帧、输入映射和 `canCancelAttack()` 公式不变。

### 2.3 保持不变项

- `N_ATTACK` 与 `N_SPECIAL` 动作数据；
- 缓存窗口和执行窗口；
- 输入边沿和更新顺序；
- 对手位置、状态和输入；
- 命中数始终为零；
- 动画、移动、伤害和效果公式；
- 停止边界；
- 观察字段和日志粒度。

### 2.4 事前预测

- 基线：更新 `2` 后待执行记录为 `110`，但 `canCancelAttack()` 始终为假；停止时仍处于 `N_ATTACK`。
- 变体：更新 `2` 后同样形成待执行记录；下一次动作请求更新读取“允许空振取消”为真，进入 `N_SPECIAL`。

两者的第二次信号、**输入识别**、动作映射和缓存事实相同；区别只在待执行记录能否越过许可门。

### 2.5 反驳与无效

预测被反驳：

- 仪器确认基线与变体都形成相同待执行记录；
- 唯一规则差异确为“允许空振取消”；
- 但两者动作轨迹仍相同。

运行无效：

- 第二次边沿没有进入来源声明的缓存区间；
- 任一运行发生接触或命中；
- 观察缓存的测试接缝改变了执行；
- 还有其他动作、帧或许可差异。

若压缩视图不保存缓存、取消资格和锁定关系，仍能在不借助作品专名或不透明参数时唯一重构并预测该差异，则 `CA-R1` 的 `CA-H03` 受到反驳。

## 3. `CA-R2`：运行过程逐步重采样还是入口锁存

### 3.1 冻结基线

制品：

- id Software 官方 GPL 源码提交 `dbe4ddb10315479fc00086f08e25d968b4b43c49`；
- `code/game/bg_pmove.c` 及必要 GPL 依赖。

初始状态：

- `pm_type = PM_NORMAL`；
- 位置 `(0, 0, 4096)`；
- 速度 `(0, 0, 0)`；
- yaw 为 `0`；
- `speed = 320`；
- `gravity = 800`；
- 无碰撞世界；
- `pmove_fixed = 1`；
- `pmove_msec = 8`。

原始输入：

| 子步 | `forwardmove` | `rightmove` |
| --- | ---: | ---: |
| `0`–`4` | `127` | `0` |
| `5`–`24` | `0` | `127` |

每步为 `8 ms`，片段在 `200 ms` 停止。关闭跳跃、蹲伏、按键、武器、水体和其他命令字段。

### 3.2 唯一变量

```text
运行中的输入采样关系 =
  基线：每个空中子步读取当前原始方向
  变体：在片段入口锁存第一次方向，后续子步继续使用锁存方向
```

夹具同时保存 `raw_cmd` 和实际提交给移动更新的 `used_cmd`。变体只改变二者之间的选择关系，不改变原始输入文件。

### 3.3 保持不变项

- 原始输入包及散列；
- 命令时间；
- 初始状态、朝向和移动模式；
- 固定步长；
- 加速度、摩擦、重力和速度公式；
- 碰撞、点内容和 `SnapVector`；
- 状态精度与停止时间；
- 轨迹记录字段。

### 3.4 事前预测

- 基线：子步 `5` 起，实际读取方向转为右向；随后水平第二轴出现非零速度与位移。
- 变体：实际读取方向始终为片段入口的前向；整个片段 `velocity[1] = 0` 且 `origin[1] = 0`。
- 两者仍共享相同初态、停止时间、原始输入轨迹和“空中移动”外部标签。

完整数值轨迹用于复算；硬判据只使用“Y 始终为零／出现非零”，避免把可接受的跨平台末位漂移误当作机制差异。

### 3.5 反驳与无效

预测被反驳：

- 日志证明 `used_cmd` 已按两种采样关系分化；
- 其他规则状态和初始条件一致；
- 但空间轨迹在硬判据上相同。

运行无效：

- 任一步离开冻结的空中过程；
- 碰撞回调返回非空接触；
- 兼容补丁改变运动语义；
- `used_cmd` 未按冻结策略分化；
- 步长、浮点平台或坐标约定没有冻结。

若只有动作 ID、初态、停止时间和普通端点字段的压缩视图仍能恢复中途采样许可并事前预测两条轨迹，则 `CA-R2` 的 `CA-H03` 受到反驳。

## 4. `CA-R3`：候选立即裁定还是延迟裁定

### 4.1 冻结基线

制品：

- osu!lazer 标签 `2026.726.0-lazer`；
- 提交 `5da71008b082d1a77e4bb301dc98886f1f24b895`；
- .NET 8；
- 标准 osu! 规则集。

初始状态：

- 一个 `HitCircle`；
- 整体难度 `5`；
- 无 Mod；
- 无其他物件；
- 光标固定在圆心；
- `StartTime = T`；
- 手动时钟和确定性调度器；
- `CheckHittable` 固定返回允许命中。

输入在 `T` 只产生一次有效按下候选，并保持至裁定完成。记录候选时刻、裁定调用时刻、相对偏移、判定窗口、正式结果、`RawTime`、结果通知、已判定状态及同一物件再次接受输入的许可。

冻结提交在难度 `5` 时的“极佳”半窗为 `49.5 ms`，“尚可”半窗为 `99.5 ms`。正式排练必须从实际对象重新读取并断言这些值；断言失败则本版本运行无效。

### 4.2 唯一变量

```text
候选到裁定的调度关系 =
  基线：候选发生时立即调用同一结果更新路径
  变体：候选发生后 75 ms 调用同一结果更新路径
```

`75 ms` 严格位于两个冻结判定窗之间。变体只调度调用，不改变 `ResultFor()`、窗口、可命中检查、结果写回、计分或效果代码。

### 4.3 保持不变项

- 候选发生时间、位置、按键和次数；
- 物件、难度与判定窗口；
- 手动时钟推进轨迹；
- `CheckHittable`；
- `ResultFor()` 与 `ApplyResult()`；
- 计分、组合数、反馈和结果通知代码；
- 停止边界；
- 后台非用户更新的调度。

### 4.4 事前预测

- 基线：裁定偏移为 `0 ms`，正式结果为 `Great`，`RawTime = T`。
- 变体：裁定偏移为 `75 ms`，超出“极佳”但位于“尚可”窗口内，正式结果为 `Ok`，`RawTime = T + 75 ms`。
- 两者都只有一个候选按下和一个正式结果；差异来自候选到裁定之间的时间关系。
- 基线在 `T` 关闭同一物件的后续输入机会；变体在 `T + 75 ms` 才关闭。这里只判断规则机会，不推断玩家会不会再次输入。

### 4.5 反驳与无效

预测被反驳：

- 日志确认两个实际裁定偏移分别为 `0 ms` 与 `75 ms`；
- 实际窗口仍为 `49.5 ms` 与 `99.5 ms`；
- 其余路径相同；
- 但结果不是 `Great` 与 `Ok`。

运行无效：

- 候选时刻不同；
- 普通更新在 `75 ms` 前提交了正式结果；
- 调度器没有在精确时刻调用；
- 窗口、可命中检查或计分代码同时变化；
- 输入形成多次候选。

若压缩视图合并候选发生、结果更新时间和正式事件后，仍能在不加入“延迟裁定”答案标签时唯一重构并预测差异，则 `CA-R3` 的 `CA-H03` 受到反驳。

## 5. 组级负对照：装饰命中动画

沿用 `CA-R3` 的制品和单圆夹具：

```text
命中动画 =
  A：开启
  B：关闭
```

保持输入、候选、裁定、窗口、正式结果、计分、组合数和反馈语义相同。事前预测：

- 两次运行的正式结果都是 `Great`；
- `RawTime`、结果通知、计分、组合数和机制状态散列完全相同；
- 只允许绘制变换、淡出路径或呈现树不同；
- 不要求逐像素图像一致。

若出现任何机制状态差异，判为负对照失败、来源误读或测试污染。它不能被用作 CA-01 的支持证据。

## 6. 重构判定表

独立重构者不需要复述来源函数名，但必须恢复以下结构：

| 角色 | 不可缺少的恢复项 |
| --- | --- |
| `CA-R1` | 第二次信号被识别并映射为另一动作请求；请求先形成待执行记录；记录的执行由单独许可门控制；许可在后续更新重新检查；输入识别不等于新动作已经实例化 |
| `CA-R2` | 同一过程有重复更新机会；每个子步读取哪一份输入；输入怎样改变期望方向并写回速度与位置；中途方向属于过程调制而不是新动作；停止边界 |
| `CA-R3` | 候选按下与正式结果不同；裁定在调用时读取时间；时间偏移进入窗口分类；正式结果、效果提交和结果通知的顺序；延迟调度怎样改变分类 |

每项还必须指出无法由材料唯一确定的分叉。作品名猜对、结果词猜对或复述源码标识符都不能补偿结构遗漏。

## 7. 变体判定表

| 角色 | 必须正确预测 | 不能作为通过依据 |
| --- | --- | --- |
| `CA-R1` | 两案都缓存；只有允许空振取消的变体进入新动作 | “变体更宽容”“玩家更容易连招” |
| `CA-R2` | 基线的水平第二轴出现非零分量；锁存变体该轴始终为零 | “控制更灵活”“移动手感不同” |
| `CA-R3` | 相同候选分别得到 `Great` 与 `Ok`，`RawTime` 相差 `75 ms`，后续输入机会在各自裁定时关闭 | “判定更严格”“玩家会感到延迟” |
| 负对照 | 机制日志相同，只有装饰动画路径不同 | 逐像素一致或审美判断 |

预测者必须提交结构结果、推导链、假设和 `indeterminate` 条件。置信度可用于诊断，不进入通过判定。

## 8. 四项硬条件的证据职责

每个角色分别接受 `CA-H01`–`CA-H04`：

| 硬条件 | 本轮怎样检验 |
| --- | --- |
| `CA-H01` 来源确定性 | 来源编码与独立忠实度审核能定位待测边界、顺序和变量；必要事实不能是猜测 |
| `CA-H02` 重构 | 丰富视图的独立重构恢复本角色全部不可缺项 |
| `CA-H03` 压缩别名化 | 机械生成的压缩视图在不偷渡答案时不能唯一恢复或区分待测关系 |
| `CA-H04` 单变量预测 | 预测在运行前冻结，并与确定性输出按预登记算法比较 |

四项是合取关系。某一角色来源不足、丰富视图重构失败、压缩视图仍然充分，或预测错误，都不能由其他角色或负对照成功补偿。

## 9. 预测材料与结果材料分离

预测任务只获得：

- 冻结基线表示；
- 变体的一个逻辑关系；
- 初始状态与原始输入；
- 允许的结果字段；
- 容差和停止边界。

它不得获得：

- 变体运行轨迹；
- 实际终态或结果值；
- 预期答案；
- 他人重构或预测；
- 源码中的项目专名和带答案的字段名。

CA-SR 的 `atomic_projection` 只保留允许的效果类型和输出通道，不保留本轮已经执行出的结果值。实际轨迹与结果必须在全部首次预测冻结后才生成或揭示。

## 10. 本决定没有证明什么

冻结变体与预测并不表示：

- 三个工程已经可构建；
- 预测已经正确；
- 丰富表示一定可被重构；
- 压缩表示一定发生别名化；
- 任何新**原语**应当加入候选表；
- 任一变体更好玩、更困难或更适合玩家。

这些结论只能由 CA-06 的冻结规则和 CA-07 之后的正式轮次产生。
