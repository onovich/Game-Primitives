- 状态：已冻结；可进入 CA-04 表示与 CA-05 变体设计
- 日期：2026-07-27
- 前序决定：[CA-01 核心命题](continuous-action-pilot-ca-01.md)、[CA-02 案例职责架构](continuous-action-pilot-ca-02-case-roles.md)

## 1. 决策

三个核心角色分别采用：

| 角色 | 正式来源锚点 | 冻结片段 | 受控变量的职责 |
| --- | --- | --- | --- |
| `CA-R1` 识别—锁定入口 | *FOOTSIES* 标签 `1.5.0`，提交 `7eaaad799bb7912625c15af9407c2c67e6305d75` | F00 的普通攻击运行中，第二次攻击边沿被映射并缓存为中立特殊攻击请求 | 已识别请求能否越过取消资格门并成为新**规则动作** |
| `CA-R2` 调制—轨迹运行 | id Software *Quake III Arena* GPL 源码提交 `dbe4ddb10315479fc00086f08e25d968b4b43c49` | 无碰撞空中移动段中，原始方向输入在固定子步之间改变 | 同一**过程**每步重采样输入，还是只在进入片段时锁存 |
| `CA-R3` 候选—裁定出口 | osu!lazer 标签 `2026.726.0-lazer`，提交 `5da71008b082d1a77e4bb301dc98886f1f24b895` | 单个圆形物件在开始时间收到一次有效候选按下 | 候选立即进入裁定，还是延迟后再沿同一路径形成正式结果 |

条件角色 `CA-R4` 暂不启用。osu!lazer 同时提供一项只改变命中动画开关的组级负对照；该对照不是第四个案例角色。

## 2. 为什么选择这三个制品

入选顺序依据：

1. 来源和版本能否精确定位；
2. 待测边界能否由一手规则或源码查询；
3. 是否可以只改变一个命名清楚的因果关系；
4. 输入、状态和结果能否在固定时间基准上复算；
5. 是否真的可能反驳 CA-01，而不只是用名作说明观点；
6. 公开测试制品的版权边界能否处理；
7. 读者熟悉度与类型代表性。

三个制品分别来自格斗、第一人称动作与节奏判定，但“覆盖三个类型”不是选择理由。它们的共同价值在于分别隔离输入到动作、运行过程到轨迹、候选发生到正式裁定三个接口。

## 3. `CA-R1`：*FOOTSIES* 1.5.0

### 3.1 身份

- 官方项目页与 GitHub 正式发布均把公开版本标为 `1.5.0`；
- 标签 `1.5.0` 指向提交 `7eaaad799bb7912625c15af9407c2c67e6305d75`；
- 声明的 Unity 编辑器版本为 `2018.1.1f1`；
- 战斗使用 `FixedUpdate`，工程固定步长为 `0.02 s`。

候选扫描曾以同一提交上的标签 `1.6.0` 记录制品，但该标签的发布附件命名存在额外版本歧义。正式测试改用与官方项目页、发布页和源码提交能够直接对应的 `1.5.0`，不声称任何发布二进制与源码逐字节相同。

### 3.2 冻结观察片段

观察 F00 从 `STAND` 进入 `N_ATTACK` 后，在取消表允许缓存的动作帧收到第二次攻击边沿。来源把该边沿映射为 `N_SPECIAL` 请求：

```text
第二次攻击边沿
→ N_SPECIAL 请求
→ 取消表允许缓存
→ 待执行记录
→ 取消资格检查
→ 新动作或继续原动作
```

对手固定在攻击范围外，使命中计数保持为零。这样不需要同时改变碰撞位置和命中时机，入口角色只检验“请求已被识别并缓存，但是否取得执行资格”。

### 3.3 可执行性门槛

正式夹具必须：

- 从干净提交在声明工具链上构建未修改基线；
- 用脚本直接提交冻结 `InputData`，不使用人工键盘时序；
- 记录输入边沿、动作编号、动作帧、命中计数和待执行动作；
- 只用测试访问器观察私有缓存，不让反射或日志改变执行；
- 机械证明对手始终不在攻击范围，基线和变体的命中计数都为零；
- 将规则补丁与仅用于观察的仪器补丁分开保存。

若 Unity 版本无法取得，或启动必须修改多项玩法逻辑，本案停止，不用重写小模型冒充原作运行证据。

## 4. `CA-R2`：id GPL 空中移动模块

### 4.1 身份

- 使用 id Software 官方 GPL 仓库提交 `dbe4ddb10315479fc00086f08e25d968b4b43c49`；
- 源码常量自报 `Q3 1.32b`；
- 正式案例名称是“该 GPL 源码快照的移动模块”，不声称它与任一零售平台可执行文件逐字节相同；
- 不使用商业关卡、美术、音频或其他零售数据。

### 4.2 冻结观察片段

夹具建立无碰撞世界和固定空中状态，`pmove_fixed=1`、`pmove_msec=8`。原始命令先保持前向，再切换为右向。来源中的 `PM_AirMove()` 在每次更新从当前命令取得前后、左右分量，再计算期望方向、加速度和空间轨迹。

```text
当前原始命令
→ 本子步读取方向
→ 期望方向
→ 速度更新
→ 位置写回
```

本案只检验运行中的同一系统过程是否继续接受新方向。武器、跳跃、水体、碰撞事件和正式伤害效果全部排除。

### 4.3 可执行性门槛

正式夹具必须：

- 首先编译并执行未修改的官方移动模块；
- 固定 C 编译器、选项、结构体初始化、浮点平台和 `SnapVector` 实现；
- 保存原始命令与模块实际读取命令，不能只保存最终位置；
- 证明所有子步持续处于冻结的空中分支；
- 将现代编译兼容补丁、测试仪器和规则变体分成三个补丁；
- 使用对数值漂移不敏感的方向性判据，并同时保留完整逐步轨迹。

若旧模块必须经多项语义修改才能链接或运行，结果记为结论不定并启用 SuperTuxKart 备选，不把移植修复当作来源规则。

## 5. `CA-R3`：osu!lazer 2026.726.0

### 5.1 身份

- 使用 ppy 官方仓库标签 `2026.726.0-lazer`；
- 标签指向提交 `5da71008b082d1a77e4bb301dc98886f1f24b895`；
- 冻结提交的工程使用 .NET 8；
- 只使用标准 osu! 规则集、项目自建的单物件测试和手动时钟，不使用在线成绩、玩家数据、商业音乐或原作皮肤。

### 5.2 冻结观察片段

单个圆形物件在 `StartTime = T` 收到一次有效按下。来源中的命中接收器先确认候选按下，随后调用结果更新；结果更新在调用当时读取 `Time.Current`，计算相对时间偏移，选择正式结果，写入 `RawTime` 并通知后续处理者。正式结果还使该物件进入已判定状态，关闭它再次接受输入的响应机会。

```text
候选按下
→ 结果更新取得当前时间
→ 判定窗口分类
→ 正式结果写回
→ 计分与反馈取得结果
```

本案保持候选按下的世界时间完全相同，只改变候选到结果更新之间的调度关系。它比单纯改变判定窗口参数更直接地检验“候选发生不等于正式事件已经提交”。

### 5.3 可执行性门槛

正式夹具必须：

- 从干净提交恢复依赖并运行现有测试框架；
- 使用可精确推进的手动时钟和确定性调度器；
- 记录候选时刻、实际裁定时刻、窗口值、结果、`RawTime` 与结果通知；
- 记录已判定状态与同一物件再次接受输入的许可何时关闭；
- 证明基线与变体的物件、位置、按键、候选时刻、判定函数、计分和效果代码相同；
- 在任何结果执行前冻结变量、预测和结果读取方法。

若调度器实际时刻不在冻结区间，或后台普通更新在预定裁定前已经提交结果，该次运行无效；不得事后调整输入或窗口挽救预测。

## 6. 备选与停止规则

| 正式席位 | 第一备选 | 切换条件 |
| --- | --- | --- |
| `CA-R1` *FOOTSIES* | *Celeste 64* `v1.1.1` / `bfc7a3ba…` | 声明 Unity 工具链不可得；干净基线无法构建；为启动必须改变玩法语义 |
| `CA-R2` id 移动模块 | SuperTuxKart `1.5` / `1fb491f5…` | 现代兼容修改无法与规则逻辑分离；确定性夹具不能保持同一空中分支 |
| `CA-R3` osu!lazer | 同一官方仓库中另一个明确标签 | 冻结标签依赖无法恢复；重选后须重新做身份、源码与窗口审核 |

备选不是静默替换。发生切换时：

1. 保留失败制品、日志和原因；
2. 新建 CA-03 小版本；
3. 重新冻结来源身份、片段、变体与事前预测；
4. 不继承旧预测的通过资格。

## 7. 来源与测试制品的边界

每个正式席位同时承担两种职责：

- 来源锚点：证明原作或源码快照确实存在待测关系；
- 受控变体：由项目在同一来源基础上改变一个逻辑变量，产生可执行反事实。

受控变体不是原作规则，也不因使用名作源码而获得额外真实性。书中可以用原作解释边界；正式强检验只依据冻结源码、夹具、补丁、输入和输出。

## 9. 冻结程度

CA-03 冻结：

- 作品或源码快照；
- 标签与完整提交；
- 核心观察片段；
- 每个角色要隔离的因果接口；
- 第一备选与停止规则；
- 版权和身份表述边界。

CA-03 尚未声称：

- 工程已经成功构建；
- 具体补丁、输入和输出已有最终散列；
- 任何事前预测已经通过；
- CA-01 或 CA-SR 0.1 获得支持；
- 玩家会如何操作或体验这些变体。

这些结果只能由后续彩排和正式轮次生成。
