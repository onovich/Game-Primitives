# 从逻辑解谜组到连续行动组的组间方法复核

- 状态：复核完成；后续 `CA-01`–`CA-07` 已接受并冻结
- 日期：2026-07-27
- 范围：测试说明、输入隔离、污染记录、输出格式与工作负担
- 前序结果：[`logic-001` 正式比较报告](calibration-tests/logic-pilot/runs/logic-001/reports/logic-001-comparison.md)
- 方法依据：[第二轮案例校准协议](calibration-cycle-2-protocol.md)与 [ADR 0102](../docs/adr/0102-run-the-logic-puzzle-pilot-before-continuous-action.md)

## 1. 复核结论

`logic-001` 证明了一套可审计的强检验证据链能够实际运行：来源编码、忠实度审核、冻结输入、彼此不可见的首次提交、答案承诺、揭示、逐项比较与污染保留都形成了可复算记录。

这套**证据链骨架可以迁移**，但逻辑组的具体包、角色数量、匿名化目标和 GP-SR 0.1 不能原样复制到连续行动组。进入下一组前必须做四项修订：

1. 把**作品身份熟悉度**与答案、预测或他人提交的**完整性污染**分开；
2. 把重构、变体预测和结果判定各自的通过标准分开，再事前声明怎样汇总为组级结论；
3. 为连续时间、输入采样、动作生命周期、碰撞／结算与反馈增加可复现的实现或轨迹证据；
4. 只保留对当前主张有贡献的角色和制品，并对新增的变体流程做增量彩排。

本复核不改变任何**原语候选**状态，不把 `logic-001` 外推为 GP-SR 0.1 普适，也不替代校准门 D。

## 2. `logic-001` 给出的直接方法证据

| 复核维度 | 观察 | 迁移判断 |
| --- | --- | --- |
| 测试说明 | 四份提交均通过 Schema，没有提交使用 `indeterminate`；自然语言理由足以定位判断依据 | 保留“结构化答案＋自然语言理由”，但每种任务使用独立**判定表** |
| 相同输入与首次提交 | 同类执行者收到相同字节，首次提交在双方返回前彼此不可见 | 保留 |
| 会话隔离 | 空白会话能够隔离对话上下文，但共享文件系统不是权限边界 | 保留**程序性独立**表述，不升级为安全隔离 |
| 身份匿名化 | 四名测试者都识别或怀疑原型，全部证据按冻结规则降级 | 不再把“未认出作品”作为连续行动组的主要成功条件 |
| 答案隔离 | 无提交声明答案或他人提交暴露；承诺在揭示后精确复算 | 保留并扩展为答案／预测／结果隔离 |
| 判定汇总 | `LC-01`、`LC-02` 需要把来源重构与匿名夹具判断作为互补证据汇总 | 下一组必须事前写明“哪个任务证明哪个子命题” |
| 行为边界 | 报告没有依赖玩家策略、难度、平衡或体验主张 | 保留行为触发门 |
| 工作负担 | 正式清单含 32 个公开制品，并使用 `1＋1＋2＋2` 六个执行角色 | 证据链有效，但角色数和自定义制品不能机械继承 |

## 3. 直接保留的方法骨架

### 3.1 来源与表示先冻结

连续行动组仍应先确定作品、版本、平台、配置、内容实例与观察范围，再由**来源编码者**建立结构描述，并由不同执行者完成**来源忠实度审核**。无法由来源确定的实现细节必须标为未知，不能由游戏常识补全。

### 3.2 首次提交与不可覆盖历史

独立任务继续使用相同冻结输入、彼此不可见的**首次提交**和逐字节哈希。输入、任务语义、基准或承诺在首份提交后发生变化时建立新轮次，不回写旧轮次。

### 3.3 承诺、揭示与逐项比较

任何测试者在结果揭示前作出的答案或预测都应先冻结。若结果由项目执行得到，至少冻结：

- 预测文本及其 SHA-256；
- 基线与变体的精确制品标识；
- 输入脚本或操作轨迹；
- 结果轨迹与比较方法；
- 揭示顺序与异常记录。

承诺只证明预测或答案没有事后改写，不证明它正确。

### 3.4 Schema、哈希与主张边界

继续以 JSON 保存结构化数据真值，以 Markdown 保存说明和阅读视图。制品清单、Schema 校验、哈希、污染声明和范围外主张必须保留。玩家行为或体验主张仍按第二轮协议触发单独证据。

## 4. 进入连续行动组前必须修订的部分

### 4.1 把熟悉度与完整性污染拆成两个轴

逻辑组把原型识别统一记为 `downgraded`，这对暴露重构自足性的风险有用，但不适合作为连续行动组的单一污染结论。经典平台、格斗或节奏作品很容易仅凭动作结构被认出。

下一组应分别记录：

| 轴 | 典型情况 | 对结果的作用 |
| --- | --- | --- |
| **熟悉度限制** | 认出作品、玩过相近机制、知道公开规则 | 限制“仅凭结构描述即可重构”的证据强度；不自动使预测或结构判断失效 |
| **完整性污染** | 提前看见答案、结果轨迹、他人提交或被禁止的包外材料 | 按影响使单份提交降级、失效，或使轮次无效 |

同一暴露对不同任务的影响可能不同。例如，认出《超级马力欧兄弟》会削弱重构测试对描述自足性的证明，却不必然污染一项已经事前冻结、只比较两个可执行变体的状态轨迹预测。报告必须逐任务说明影响，不能只给整份提交一个笼统标签。

### 4.2 分开任务判定表与组级汇总

连续行动组在冻结前应建立三张表：

1. **重构判定表**：每个案例必须恢复哪些实体、状态、时间关系、输入映射、动作生命周期、结算和反馈；
2. **变体判定表**：隔离变量、保持不变项、事前预测、反驳条件与结果读取方法；
3. **汇总映射**：每个组级硬条件由哪些重构项、预测项和结果项共同支持。

不得用“总体方向差不多”替代逐项判定，也不得要求重构者猜测被隔离的变体结果。若某个组级结论需要两种任务共同支持，必须在揭示前写明各自职责。

### 4.3 增加连续实现与轨迹证据

GP-SR 0.1 是逻辑组的冻结快照，不能直接改写。连续行动组需要另行冻结新的表示快照或伴随剖面，至少能记录：

- 输入设备与**行动实现载体**；
- 输入采样、缓冲、识别和映射；
- 动作开始、承诺、活动、恢复、取消等案例特定里程碑；
- 连续或离散时间基准、更新步长与时钟所有者；
- 位置、速度、接触、碰撞候选与结算顺序；
- 动作、事件与过程之间的触发关系；
- 状态效果与向指定观察者呈现的反馈；
- 规则文本、实现事实、外部测量和派生评价的证据来源。

测试输入不必暴露源代码，但必须提供足以复算结论的规则、实现说明或冻结轨迹。帧率、采样、容差、平台差异等无法确定时应保留为 `source_underdetermined`，不能写成默认常量。

### 4.4 设计变体必须先预测、后运行

每项变体至少冻结：

```text
基线制品
+ 一个隔离变量
+ 保持不变项
+ 结构预测
+ 反驳条件
+ 结果取得方法
```

结构预测优先落在输入识别、动作合法性、结算、实际效果、状态轨迹、反馈或系统评价。使用“更顺手”“更难”“更刺激”“玩家会改变策略”等表达时，结构轨迹只能算前半段证据，必须另行触发行为取证。

如果使用可执行原型或游戏构建，应冻结构建版本、配置、输入轨迹、运行环境和结果文件的校验值。若只做规则推演，也必须冻结推演程序、初始状态和停止条件。

### 4.5 角色与制品按主张配置

不自动复制 `1＋1＋2＋2`：

- 来源编码与来源忠实度审核仍分别需要独立角色；
- 重构测试仍至少需要两份首次提交，便于区分偶然遗漏和稳定歧义；
- 设计变体的预测者、执行者与结果判定者是否分离，取决于结果能否由程序直接读取；
- 只有提出原语或语法边界主张时才增加独立标注；
- 只有提出玩家活动、技能、难度、平衡或体验主张时才增加行为取证。

通用信封、提交、清单、承诺和揭示 Schema 可以复用；只有连续轨迹和变体结果使用专门 payload Schema。新增的预测—执行—揭示链应先完成一次小型**增量彩排**，无需重演已经通过的纯算术流程。

## 5. 暂不在本次复核决定的事项

- 不选择连续行动组的具体游戏、版本或内容实例；
- 不决定连续时间、碰撞、输入或反馈是否分别成为**原语**；
- 不把动作生命周期或行动实现载体升级为公开理论层级；
- 不判断任何变体更有趣、更困难或更适合玩家；
- 不决定门 D 是否通过，也不扩展到社会裁定、硬核模拟或持续世界。

## 6. 连续行动组的启动清单

完整取证前必须依次冻结：

1. 一个可能被反驳的核心命题；
2. 锚点、对照、纵深或边界案例的职责；
3. 每个案例的版本、平台、配置、内容实例和观察范围；
4. 连续行动表示快照与轨迹证据格式；
5. **重构判定表**、**变体判定表**和组级汇总映射；
6. 熟悉度限制与完整性污染的逐任务影响规则；
7. 行为主张范围、执行角色、制品位置和增量彩排条件；
8. 事前预测承诺与正式派发前的人工放行门。

完成本复核只意味着连续行动组可以进入上述前置设计，不意味着正式测试已经开始。
