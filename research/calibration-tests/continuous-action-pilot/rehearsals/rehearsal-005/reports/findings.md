# rehearsal-005 结论

盲测回答接口的聚焦彩排通过。它解除的是 `rehearsal-004` 暴露的“完整提交信封不可操作”阻断，不是连续行动理论结论，也不是正式盲测授权。

## 覆盖

本轮用两个彼此隔离的全新空白会话覆盖了两种最重要的回答形态：

- `condition-v01` 首次重构把结构判为唯一可恢复，首次预测给出基线 7、变体 4；
- `condition-v02` 首次重构保留多个相容结构，首次预测回答不确定并给出三个完整、配置寻址的相容替代。

四份原始 payload 都在第一次返回时通过，没有向同一执行者发送 Schema 错误或修订要求。两个执行者都在第一阶段冻结后由原会话继续第二阶段。

## 接口结论

新分工可以实际运行：

```text
执行者：污染自报 + 语义答案
保管工具：任务、条件、actor、session、时间与散列
```

工具能够：

- 从任务包绑定视图、结构模板与变体；
- 在预测阶段核对同一 actor/session 和前阶段精确散列；
- 拒绝案例、配置、观察量、类型、容差或相容替代覆盖不完整的 payload；
- 在派生提交中直接绑定原始 payload、信封、Schema 与工具；
- 使用相同输入重复生成逐字节相同的提交。

`submitted_at` 现在来自原始回答到达后捕获的机器信封，不再由盲测者猜写。

## 仍然存在的边界

- 机器信封绑定了实际派发材料，但不能单独证明操作系统或会话实现的绝对隔离；本轮还依赖空白会话编排与禁用工具。
- 协作通道返回的是 JSON 文本而不是带传输层签名的字节流；仓库中的“原始 payload”是首次返回文本加项目统一末尾换行后的归档字节。
- 模板降低的是结构错误，不替执行者做语义选择。可确定与不确定答案均由执行者自己形成。
- `rehearsal-004` 发现的执行原始文件与最终报告缺少直接结构化 SHA 引用，属于正式执行／报告 Schema 的另一项准备工作，不由本接口修订解决。

## 放行影响

接口修订的聚焦复测要求已经满足。下一步可以制作正式 `continuous-001` 的来源、任务、夹具、执行与报告制品，并在全部材料冻结后准备 CA-07 的一次性人工门。

这不等于现在已经放行。正式执行者不得派发，正式精确结果不得运行，直到作者明确说“放行正式连续行动试验”。
