# rehearsal-004 结论

本轮通过了 CA-07 指定的六项新增程序检查。这只说明“重构冻结 → 预测冻结 → 执行 → 揭示 → 报告”的证据链可以闭合，不是连续行动理论的证据，也不构成正式盲测放行。

## 已验证

- 冻结集合的逐项散列、Schema 散列、任务包引用、规范前像与根摘要可以由独立校验器复算。
- 两条入选链都满足“同一执行者继续第二阶段”，并由第二阶段制品绑定自己的第一阶段散列。
- 两种条件保持隔离；失效执行者的上下文没有传给替补。
- 两份入选预测先由规范前像绑定，确定性执行随后开始；执行结果先冻结，真值随后揭示。
- 真值文件、随机数、承诺、预测集合、执行结果和揭示记录形成逐字节可复算的闭包。

## 程序通过不等于接口通过

本轮共保留八份 Schema 无效提交，另有三份虽然第一阶段有效、但因同一执行者的第二阶段失效而退出的重构。错误集中在完整 `role-submission` 信封的元数据枚举、嵌套字段名、配置 ID、类型化值和必填字段，而不是条件材料的实质判断。

最后入选的 v02 预测是在派发方给出完整候选响应外壳后完成的。外壳没有泄漏实际执行结果 4；其中的数值只作为执行者需要自行选择、修改或删除的假设性相容替代。但是，这次成功只能验证既定证据链在“格式已被强约束”时能够运行，不能证明盲测执行者可以可靠地自由手写完整提交信封。

因此，正式人工门仍被以下工程问题阻断：

1. 派发工具应机械生成不可由盲测执行者决定的元数据和外层信封；
2. 盲测执行者只填写最小语义 payload；
3. 原始 payload 必须原样保存并以 SHA-256 绑定到机械生成的正式提交；
4. 包装器不得修补、推断或重写语义字段；
5. 新接口须通过一次聚焦的空白会话复测，再进入正式人工门。

## 归档说明

重试期间的提交按产生顺序增量归档，未等到所有重试结束后再一次写入。这是对原计划“同阶段一起归档”的偏离，但没有破坏本轮的盲化边界：替补会话无法读取共享工作区，另一条件和其他提交没有进入其上下文，并且确定性执行直到最终有效预测集合冻结后才开始。

正式轮次不应照搬这种人工重试方式。包装器和阶段收集器应先在隔离暂存区接收原始 payload，完成机械包装与 Schema 校验，再以一个阶段提交归档全部有效首次提交；无效 payload 仍应原样保留在审计区。

## 补充审计限制

- 入选 v02-r8 重构与预测自报的 `submitted_at` 均晚于各自 Git 冻结时间，预测自报时间还晚于执行开始时间。因此本报告的顺序判断只采用 Git 提交与实际执行记录，不采用执行者自填时间。ADR 0116 已把提交时间改为保管工具在收到原始 payload 后生成。
- 条件隔离由任务禁令、空白会话编排、actor/session 与污染自报共同支持；本轮没有单独的派发转录。新机器信封会绑定任务、输入和前阶段，缩小这一审计缺口，但不能单独证明运行环境绝对隔离。
- `raw-stdout.jsonl` 与 `invocations.json` 没有被 `trace-bundle.json` 或 `result.json` 以文件 SHA 字段直接引用；闭包依赖先行 Git 提交、逐行记录 ID 和人工复算。`rehearsal_report` 本身也只在证据文字中引用上游散列。这不推翻本轮预先定义的六项检查，但正式包若追求全机器闭包，应在执行与报告 Schema 的下一版本补上直接引用。
