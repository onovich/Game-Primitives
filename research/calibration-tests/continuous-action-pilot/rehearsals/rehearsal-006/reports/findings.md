# rehearsal-006 结论

协议 0.1.1 的参与者接口聚焦彩排通过。四名独立空白参与者都能在没有追加格式提示、没有工具访问的情况下，连续完成结构重构和中性变体预测。

这解除的是“Schema 中存在合法对象，但盲测参与者未必能仅凭派发材料构造它”的程序阻断。它不是连续行动理论的行为证据，也不是正式试验结果。

## 实测设计

本轮为两个条件各设置两个独立席位：

| 条件 | 席位 | 第一阶段 | 第二阶段 |
|---|---|---|---|
| `condition-v01` | A | 唯一可恢复 | 确定：基线 7、变体 4 |
| `condition-v01` | B | 唯一可恢复 | 确定：基线 7、变体 4 |
| `condition-v02` | A | 多种结构兼容 | 不确定；给出两套兼容替代 |
| `condition-v02` | B | 信息不足 | 不确定；给出两套兼容替代 |

两名 V01 参与者的措辞、局部 ID 和事实拆分不同，但恢复了同一语义结构。两名 V02 参与者对“不足”采用了不同粒度：一人枚举多个结构，另一人直接清空不可恢复项；两种回答都在模板允许的分支内，并在预测阶段汇合为相同的“不确定”结论。

## 参与者可构造性

四个席位分别位于四个 projectless 任务目录，使用相同模型 `gpt-5.6-sol` 与 `high` 推理强度。同条件 A/B 收到逐字相同的第一阶段提示，四人第二阶段收到逐字相同的中性提示。

每个任务都满足：

- 第一阶段是任务的第一轮，不存在更早对话；
- 每阶段只有一条最终 JSON；
- 没有 commentary、中间答案、工具或命令项；
- 没有纠错或格式补充轮次；
- 第二阶段在原任务中继续，而不是迁移到新任务；
- 原始回答首次即通过 Schema、模板分支和阶段绑定检查。

因此，协议 0.1.1 已经把参与者职责收敛到可执行的界面：

```text
参与者：污染自报 + 语义选择
保管工具：任务、条件、actor、session、时间、散列与前阶段绑定
```

## 这次彩排真正证明了什么

它证明模板不只是“理论上允许”确定与不确定回答，而是空白参与者能够实际选中正确分支：

- 材料显式给出采样关系、更新过程和步骤内顺序时，参与者可以恢复结构并推出变体结果；
- 材料只给出操作发生、输入轨迹和写入字段，而不声明这些元素之间的关系时，参与者不会仅凭 `op.accumulate` 这个名称臆造唯一机制；
- 不确定答案可以同时保留类型安全的主状态和至少两套完整、配置寻址的兼容替代。

V02 的 `confidence_percent=100` 表示参与者确信“当前材料不足以唯一决定结果”，不是确信某个隐藏数值。后续报告解释置信度时必须保持这一区分。

## 完整性边界

- projectless 任务、不同 thread ID、不同目录与空白首轮提供的是可观察的会话隔离证据，不是操作系统级或密码学意义的绝对隔离证明。
- 仓库中的原始 payload 是首次最终文本按项目 JSON 排版和统一末尾换行归档后的字节；其内容没有语义修订。
- 本轮没有接触正式 `runs/`、真值、runner 或 comparator，不能据此判断任何正式理论假设。
- 彩排通过只清除 `rehearsal-006` 的停止条件；后续试验仍须拥有自己的冻结材料、边界检查与放行记录。

## 程序影响

参与者接口 0.1.1 可以作为下一轮正式准备的基础，不再需要继续增加格式提示。下一步应把精力从“参与者会不会填对 JSON”转回研究设计本身：明确下一轮要区分的理论问题、条件操纵、反例与停止规则，再制作新的冻结包。
