# rehearsal-006

这是协议 0.1.1 参与者接口修复的聚焦彩排，不是新的正式实验，也不产生可用于《游戏原语》理论判断的行为证据。

## 要回答的问题

`continuous-001` 已证明：一个对象在数据 Schema 中存在，不等于参与者仅凭派发材料就能构造它。`rehearsal-006` 因此只检查三件事：

1. **数据 Schema 有效**：原始回答能通过对应阶段的响应接口；
2. **模板分支闭合**：类型化模板能表达任务允许的确定与不确定分支；
3. **参与者可构造**：空白参与者无需保管者追加格式提示，就能根据任务、模板和内嵌契约完成首答。

## 范围

- 只使用一个完全合成的 `CA-R2` 案例；
- 同时覆盖 `condition-v01` 与 `condition-v02`；
- 第一阶段为结构重构，第二阶段为中性变体预测；
- 不读取、不复制、不运行 `runs/` 下的任何正式输入；
- 不生成真值、执行许可、正式结果或揭示材料；
- `continuous-001` 的冻结字节保持不变。

## 协议 0.1.1 的关键修复

- 重构与预测拥有彼此独立的阶段契约；第一阶段材料不包含第二阶段观察量规则。
- 回答模板是 **typed choice template**，明确区分冻结常量、字符串占位符、JSON `null` 和可变数组。
- `confidence_percent` 是显式的 `<integer-0-100>` 类型化槽位；参与者必须把它替换为 0 至 100 的 JSON 整数，不能把非法哨兵值当成冻结常量。
- 不确定主预测固定使用：
  - `expectation_kind=status`
  - `serialized_value=indeterminate`
  - `value_type=status`
  - `unit=null`
- 相容替代必须使用具体值和声明单位，并完整覆盖配置—观察量笛卡尔积。
- 原始参与者回答与保管者生成的提交信封分离；保管者只进行确定性的字段复制和元数据装配。

## 门前验收

派发空白参与者之前，必须由 `verify-rehearsal-006.py` 在一个不含 `runs/` 的临时白名单镜像中证明：

1. 最小重构回答通过；
2. 非空 `integrity_exposures` 重构回答通过；
3. 大写本地 ID 负控被拒绝；
4. 确定预测通过；
5. 不确定预测通过；
6. 两个完整且不同的相容替代通过；
7. 旧式固定有量纲单位模板被拒绝；
8. 参与者契约、分支闭合检查、相关 Schema 与验证器已经进入冻结集合。

修复计划的第 8 项——四个隔离空白 actor 的首答直接有效——只能在冻结并派发之后验收，不能由合成夹具替代。

## 目录

- `inputs/`：两阶段任务、类型化模板、合成视图、中性信封、契约检查与冻结协议镜像；
- `inputs/dispatch/`：四席派发计划，以及不使用 Markdown 扩展名的逐字节 `*.prompt.txt` 操作提示；
- `fixtures/positive/`：必须通过的四类原始回答；
- `fixtures/negative/`：必须失败的三个负控；
- `fixtures/assembled/`：由 0.1.1 打包器确定性生成并可重建验证的信封与提交；
- `raw/`、`envelopes/`、`submissions/`：冻结后保存四个空白 actor 的实际结果；
- `reports/`：首答有效性与整体彩排验收报告。

## 停止条件

任一 actor 首答无效、调用工具、需要追加格式提示、访问未派发材料，或两阶段不能在同一独立会话中连续完成，均保留原始记录并判定彩排失败。失败时不得建立 `continuous-002`。
