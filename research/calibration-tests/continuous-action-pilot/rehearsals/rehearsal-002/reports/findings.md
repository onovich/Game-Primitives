# rehearsal-002 结论

本轮是第二次有效的失败排演。它不产生连续行动理论证据，也不把虚构系统当作正式案例。

## 已验证

- `role-submission 0.1.1` 修复了第一次彩排发现的预测寻址缺口：同一观察量的每个预测值现在必须显式绑定配置。
- 两次 Schema 无效的首次尝试和一次 Schema 无效的替补尝试均被原样保留；有效替补从第一阶段重新开始，没有继承失败会话。
- 有效重构、预测、确定性执行、结果归档、真值揭示和报告形成了可逐字节复算的单向链。
- 两种条件在互换分配后仍产生预期的信息差：丰富视图恢复规则关系并给出确定预测，原子视图保留多个相容解释并给出按配置寻址的不定预测。

## 阻止通过的问题

`manifest.json` 的 9 个单项文件散列及其 Schema 散列都与当前冻结字节一致，但 `frozen_artifact_set_digest` 不能按 CA-07 冻结的算法复算：

```text
按 path 排序
path + TAB + file_sha256 + LF
→ SHA-256
```

按该算法得到 `fe3534849b1b1e50a62f1e1841ba4b9e774fb3c19011f8892cd47e5407b682c5`，清单记录的却是 `060a0ace37c306b55af9d06978b5f2bdac4192fcc8229ad0151c496a51514d3f`。因为清单已经冻结，不能回写正确值；本轮必须判为 `procedure_fail`。

## 另一个非阻断修订

丰富视图执行者恢复了全部受测规则，却把循环、内联、辅助函数和展开写法视为不同的“相容结构”，因此将 `uniqueness` 标为 `multiple_compatible_structures`。这暴露的不是本轮程序失效，而是“唯一”究竟按源代码实现、操作结构还是规则语义判定尚未写清。

正式派发材料应补一句等价约定：重构唯一性按受测结构记录及其可观察规则关系判断；不把只改变代码组织、但不改变这些关系的实现形式计为不同重构。若正式案例确实要求区分实现媒介，则应在受测结构中显式列出，而不能由执行者猜测。
