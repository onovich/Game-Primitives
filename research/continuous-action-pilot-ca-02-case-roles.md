# 连续行动组 CA-02：案例职责架构

- 状态：已冻结；CA-03–CA-07 已完成，尚未启动正式取证
- 日期：2026-07-27
- 前序决定：[CA-01 核心命题](continuous-action-pilot-ca-01.md)
- 接受记录：[ADR 0110](../docs/adr/0110-freeze-continuous-action-case-role-architecture.md)
- 适用范围：第二轮**连续行动与具身控制组**；本稿不选择作品，也不提出玩家行为或体验结论

## 1. 决策摘要

CA-02 采用三个核心案例角色和一个条件角色：

| 编号 | 工作角色 | 隔离的主要接口 | 必须攻击的压缩主张 |
| --- | --- | --- | --- |
| `CA-R1` | 识别—锁定入口 | **输入** → **规则动作** → **锁定点**、取消与重入 | “输入一旦被识别，动作就已经发生并完成锁定” |
| `CA-R2` | 调制—轨迹运行 | 已进入运行的**动作** → **过程** → 时间／空间轨迹 | “动作只需要一个名称、起点和终点” |
| `CA-R3` | 候选—裁定出口 | 接触／阈值 → 候选发生 → 正式**事件** → **结算**与**效果** | “世界发生、正式事件和效果提交是同一件事” |
| `CA-R4` | 反馈—再进入闭环 | 效果 → 指定观察者的**语义反馈** → 后续响应机会 | 条件角色；只在前三者无法隔离反馈时启用 |

这些名称是本轮工作角色，不进入**共享术语**，也不构成“原语到游戏”主线中的新层级。角色按检验职责定义，不按平台、格斗、节奏、竞速或体育等类型分配席位。

## 2. 为什么是三个核心角色

CA-01 检验的区间从输入识别开始，到效果提交结束。三个角色把这段区间切在两种已有边界上：

```text
信号／输入
  │
  ├─ CA-R1：识别、许可、锁定、取消、重入
  ▼
动作进入运行
  │
  ├─ CA-R2：持续调制、过程更新、时空轨迹
  ▼
首次候选发生
  │
  ├─ CA-R3：识别、分类、重检、裁定、结算、效果提交
  ▼
正式效果
```

该切分不是声称所有游戏都按三段运行。它只让每个案例冻结一个停止边界，避免同一项证据同时改变输入识别、运动过程和事件裁定。

原建议中的“承诺—展开锚点”不再使用。项目已经用**锁定点**描述撤回、替换或修正权限的变化，并明确不设“承诺原语”；继续使用“承诺”命名角色会重新制造层级和词义歧义。

## 3. `CA-R1`：识别—锁定入口

### 3.1 观察范围

开始于可定位的信号到达，结束于：

- 输入被拒绝、过期或消费；或
- 对应**规则动作**越过本案冻结的**锁定点**并进入持续运行。

本角色记录输入采样、缓冲、识别、动作映射、动作合法性、锁定、取消、替换和重新开放的响应机会。

### 3.2 必须隔离的变量

首选变量是一个识别或锁定关系，例如：

- 信号是在当前采样点还是下一个采样点被识别；
- 输入缓冲在动作获得资格前还是后过期；
- 某项取消权限在候选命中、正式命中或效果提交时消失；
- 运行期间的一次输入形成新动作、替换旧动作，还是不被识别。

变体必须保持输入轨迹、动作候选集合、进入运行后的过程规则和效果公式不变。

### 3.3 角色反驳条件

若删除输入—动作—锁定边界后，独立重构者仍能恢复所有许可、取消和重入关系，并能正确预测单变量变体，则本角色不能支持 CA-01。

## 4. `CA-R2`：调制—轨迹运行

### 4.1 观察范围

开始于动作或过程身份已经由来源确定并进入运行，结束于本案的首个候选事件。它观察：

- **过程**怎样获得更新机会；
- 运行中的信号怎样调节同一个过程；
- 状态读取、速度、方向、持续时间和空间轨迹怎样演化；
- 暂停、积压、重采样或终止怎样影响轨迹。

若中途输入生成新动作、取消或替换当前动作，交回 `CA-R1`；若输入只改变同一过程的参数或轨迹，则留在 `CA-R2`。

### 4.2 必须隔离的变量

首选变量是一项**调度语义**或过程更新关系，例如：

- 方向只在开始时锁存，还是在每次过程更新前重新采样；
- 控制权在整个过程关闭，还是在指定里程碑重新开放；
- 状态更新读取上一快照还是当前已经写回的状态。

变体必须保持初始过程状态、输入轨迹、时间基准、空间边界、碰撞／事件规则和效果公式不变。

### 4.3 角色反驳条件

若只保存动作名称、起点、终点和普通参数，仍能唯一重构中间许可与轨迹并预测变体结果，则本角色不能支持“过程边界必须显式保存”。

## 5. `CA-R3`：候选—裁定出口

### 5.1 观察范围

开始于来源承认的接触、阈值、越界或其他候选发生，结束于正式事件被写回并完成本案声明的**结算**与**效果**提交。

本角色固定完全相同的前置世界轨迹，分别记录：

- 世界中的候选发生；
- 检测、观察或分类；
- 规则是否重新检查状态；
- 哪个规则实现者有资格确认；
- 正式事件的写回时点；
- 结算与实际状态效果。

### 5.2 必须隔离的变量

首选变量是候选发生到正式事件之间的一项关系，例如：

- 接触时立即提交，还是在下一判定点重新检查；
- 阈值以连续穿越、离散快照还是容差区间判定；
- 同时候选按哪一个冻结优先级写回；
- 事件一经确认立即产生效果，还是效果在另一提交阶段生效。

变体必须保持输入、动作生命周期、前置过程、空间轨迹、候选发生和效果公式不变。

### 5.3 角色反驳条件

若把候选发生、正式事件和效果提交合并后仍能唯一重构裁定与轨迹，并正确预测单变量变体，则本角色不能支持 CA-01。

## 6. 条件角色 `CA-R4`：反馈—再进入闭环

只有同时满足以下条件才增设第四角色：

1. 前三个角色都无法在不改变世界状态和正式效果的前提下，单独改变观察者、信息内容、准确性、时机或保留方式；
2. 组级结论仍要主张“效果提交不等于参与者已经获知”是独立、不可压平的边界。

`CA-R4` 固定世界轨迹与正式效果，只改变**语义反馈**契约，并以规则定义的后续输入许可或响应机会为观察量。只比较装饰动画、音质或视觉风格不满足条件。

若结果只显示参与者取得信息的时间不同，它只能支持表示完整性；要主张玩家会改变操作、策略、难度判断或体验，必须另行触发行为取证。

## 7. 三个核心角色的交接规则

| 容易重叠的位置 | 归属判据 |
| --- | --- |
| 运行中的新输入 | 形成、取消或替换**规则动作**属于 `CA-R1`；只调节同一**过程**属于 `CA-R2` |
| 碰撞改变轨迹 | 碰撞前的检测与轨迹积分属于 `CA-R2`；来源承认的候选发生及其正式化属于 `CA-R3` |
| 裁判／系统观察与玩家观察 | 为形成正式事件而进行的观察属于 `CA-R3`；向参与者提供可用信息属于 `CA-R4` 或跨案例反馈义务 |
| 动作身份不明确 | 不由研究者事后切段；记为 `source_underdetermined`，必要覆盖缺失时结论不定 |

每个核心角色必须分别满足 `CA-H01`–`CA-H04`。一个角色的成功不能补偿另一个角色没有来源、无法重构、未发生别名化或没有事前预测。

## 8. 跨案例强制义务

无论最终使用多少作品，整组都必须满足：

1. 至少一个角色记录**行动实现载体**怎样实际改变信号形成、识别或世界耦合，而不只列设备名称；
2. 至少一个角色闭合“效果／反馈 → 后续响应机会”，但不推断玩家实际会怎样行动；
3. 每个核心角色同时拥有一手来源支持和可复算的单变量变体；两者可以来自同一开放制品；
4. 每个角色预先冻结时间基准、输入轨迹、轨迹等价标准、容差和停止边界；
5. 整组增加一个只改变帧率、日志粒度或装饰反馈、按命题不应产生机制区别的负对照；
6. 不把程序函数、动画帧或硬件采样事实直接提升为规则边界，除非规则许可、事件、效果或信息可得性会读取该差异。

## 9. 角色数不等于作品数

同一作品可以承担多个角色，但必须使用不同的冻结片段、不同的隔离变量和分别可判定的输入包。多个作品也可以共同承担一个角色，但只有当单一来源无法同时提供典型锚点与可执行变体时才增加。

CA-03 不按“每类游戏一个”配额选案。平台、射击、格斗、节奏、竞速、体育、物理模拟、体感或无障碍控制只是反例来源；入选依据依次是：

1. 来源和版本可确定；
2. 单变量边界可隔离；
3. 输入与结果轨迹可复算；
4. 能真正反驳而不只示范 CA-01；
5. 版权和公开测试制品边界可处理；
6. 读者熟悉度或垂直类型代表性。

“耳熟能详”有教学价值，但不能替代前五项。

## 10. CA-03 的输出与当前结果

CA-03 已为每个核心角色给出：

- 作品、规则集或源代码版本；
- 平台、构建、配置和具体行动片段；
- 一手来源定位与制品校验值；
- 本角色的开始、停止边界和来源不确定项；
- 预备单变量及保持不变项；
- 可执行、可推演或可重放的结果取得方式；
- 版权、熟悉度、实现噪声与行为越界风险；
- 明确的入选、备选、延期或拒绝结论。

这些信息现已在[案例与版本冻结](continuous-action-pilot-ca-03-case-selection.md)中完成；CA-04–CA-07 也已冻结表示、变体、角色和制品纪律。正式重构任务仍须等待工作区、增量彩排、正式包和一次性人工放行。
