# 连续行动组 CA-06：执行、隔离、污染与结论规则

- 状态：已冻结；等待 CA-07 制品与增量彩排
- 日期：2026-07-27
- 来源决定：[CA-01](continuous-action-pilot-ca-01.md)–[CA-05](continuous-action-pilot-ca-05-variants.md)与[组间方法复核](calibration-method-review-logic-to-continuous.md)
- 接受记录：[ADR 0114](../docs/adr/0114-freeze-continuous-action-execution-and-verdicts.md)
- 行为范围：`structural_only`

## 1. 决策摘要

正式轮次采用 `1＋1＋2＋2`：

| 工作 | 数量 | 职责 |
| --- | ---: | --- |
| **来源编码者** | 1 | 从冻结来源建立 CA-SR 0.1 规范编码 |
| 来源忠实度审核者 | 1 | 独立核对来源、表示、唯一变体、投影视图和身份泄漏 |
| 丰富视图重构／预测者 | 2 | 先独立完成**重构测试**，冻结首次提交后再完成**设计变体测试** |
| 压缩视图重构／预测者 | 2 | 对 `atomic_projection` 完成相同两阶段任务，检验压缩是否仍然充分 |

主编线程担任测试保管者，不参加来源编码、盲化重构或盲化预测。确定性夹具、运行程序和比较器属于执行设施，不增加一个需要主观裁定的角色。

本轮：

- 不增加独立标注者，因为不预先改变**原语候选**或语法边界状态；
- 不增加行为参与者，因为玩家活动、技能、难度、平衡和体验全部范围外；
- 不启用 `CA-R4`，但保留 CA-02 的载体与反馈闭环义务；
- 所有角色名称都是测试局部工作标签，不进入**共享术语**或公开理论层级。

## 2. 为什么采用丰富／压缩两组

CA-01 同时提出两个可分离的问题：

1. CA-SR 0.1 的有类型描述能否使边界被独立重构并用于预测；
2. 删除中间边界后的紧凑描述是否真的发生别名化。

因此使用同一规范事实源机械生成两种材料：

```text
canonical encoding
├── blind rich view
└── atomic projection
```

两组使用相同模型版本、参数、任务、案例顺序、变体信封和输出 Schema，只改变可见表示。不能让同一会话先看丰富视图再看压缩视图；前者会直接泄露被删除的结构。

默认执行配置：

- **来源编码者**：`gpt-5.6-sol`，`high`；
- 来源忠实度审核者：`gpt-5.6-terra`，`high`；
- 四名盲测执行者：`gpt-5.6-sol`，`high`；
- 四名盲测执行者分别从不继承项目历史的空白会话开始。

若正式轮次无法使用该模型或参数，必须修改轮次清单并在派发前重新冻结；不能运行后把不同执行条件合并成同一批次。

## 3. 独立性边界

本轮继续只主张**独立执行**和**程序性盲化**：

- 空白会话不继承其他会话的对话上下文；
- 四份首次提交在冻结前彼此不可见；
- 同一条件下的两名执行者收到逐字节相同的输入；
- 丰富组和压缩组不互换材料；
- 盲测角色不得调用工具、访问网络、读取共享文件系统、创建子任务或查看包外文档。

这不是安全沙箱。逻辑组的既有金丝雀测试已经证明不同会话仍共享文件系统；普通 workspace 或 Git worktree 只能降低误读概率，不能形成权限边界。本轮不重复该测试，也不把会话隔离外推为统计独立的人类样本。

真值、密钥、实际结果、另一种视图和其他提交在规定提交收齐前不以明文进入共享工作区。无法技术性阻止的违规依靠任务约束、提交声明和污染记录管理。

## 4. 信息可见范围

| 角色 | 可以看见 | 必须隔离 |
| --- | --- | --- |
| 测试保管者 | 全部制品、映射、承诺、提交和运行结果 | 不为盲测者提供分析答案，不参加其重构或预测 |
| **来源编码者** | 冻结来源、案例范围、CA-SR 0.1 与输出 Schema | 事前答案、精确执行结果、压缩测试结论和下游提交 |
| 来源审核者 | 同一来源包、规范编码、唯一差异清单、投影视图与 Schema | 事前预测、精确执行结果和下游提交 |
| 丰富视图组 | 去身份丰富视图、测试本地术语表、冻结任务与中性变体信封 | 作品身份、原始来源、压缩视图、答案、结果和其他提交 |
| 压缩视图组 | 去身份压缩视图、同一术语表、同一任务与中性变体信封 | 作品身份、原始来源、丰富视图、答案、结果和其他提交 |
| 确定性执行设施 | 冻结构建、初态、输入、环境、停止条件和比较器 | 不允许人工临时调参或结果解释 |

来源编码者和审核者不承担独立预测证据，因此无需假装不知道源码可能产生什么结果；他们仍不得把预期输出或 CA-05 的答案写进表示。

## 5. 来源编码与忠实度审核

### 5.1 机械预检

审核前先完成：

- JSON Schema 校验；
- 来源、编码、补丁、输入和生成器 SHA-256；
- 引用闭包与来源定位检查；
- UTF-8 无 BOM、LF、稳定排序和单一末尾换行；
- 规范编码到角色视图、丰富视图和压缩视图的机械生成；
- 身份词、来源专名和答案暗示扫描；
- 基线与变体除 CA-05 唯一逻辑关系外的语义差异检查；
- 基线与变体 `atomic_projection` 的规范化结构摘要相同；
- 中性变体信封在两种盲化条件中逐字节相同。

“结构摘要相同”不包含信封中的基线值和变体值，而是要求压缩表示没有借字段名、ID 或说明重新编码被删除的因果关系。

### 5.2 人工来源审核

来源审核者逐案检查：

1. 作品、提交、构建、**时间基准**和输入是否足以判断 `CA-H01`；
2. 来源事实是否被遗漏、曲解或越界补全；
3. 规则、实现、仪器测量和项目推导是否保持不同证据身份；
4. `source_underdetermined` 与 `representation_gap` 是否正确区分；
5. 项目变体是否只改变 CA-05 声明的一项逻辑关系；
6. 不变量是否没有被补丁、初始化或观察仪器破坏；
7. 角色视图与压缩视图是否忠实于规范事实源；
8. 盲化 ID、字段名、顺序和说明是否泄露作品或答案；
9. CA-02 的载体、反馈闭环和负对照义务是否可由制品检查。

审核结果：

- `approved`：可以进入冻结；
- `revision_required`：修订后重新审核；
- `blocked`：必要事实无法由来源裁定，或变量无法隔离。

实质异议必须绑定来源定位。编码者与审核者不通过多数票、理论偏好或“哪份更容易通过”解决分歧；无法裁定时阻止该案例冻结。

## 6. 两阶段盲测

### 6.1 第一阶段：独立重构

四名执行者先只得到相应视图和重构任务。每项首次提交必须包含：

- 恢复的结构事实；
- 支持该事实的记录或关系 ID；
- 该事实是否能唯一恢复；
- 至少一个仍兼容的分叉，或说明为什么没有分叉；
- 所有额外假设；
- 熟悉度与污染声明。

丰富视图组必须恢复 CA-05 的全部不可缺项。作品名猜对、源码函数名猜对或最终结果猜对不能补偿结构遗漏。

压缩视图组不是被要求“答错”。它们应尽可能给出紧凑材料允许的最强重构，并明确区分：

- 唯一可推出；
- 存在多个兼容结构；
- 信息不足；
- 只能依赖先验知识猜测。

四份重构首次提交全部冻结、散列且彼此隔离后，才进入第二阶段。

### 6.2 第二阶段：事前变体预测

同一会话随后收到：

- 与另一条件逐字节相同的中性变体信封；
- 变量 ID、基线值和变体值；
- 不变量 ID；
- 允许的观察字段；
- 容差和停止边界。

信封不解释变量的因果职责。丰富视图可通过正式关系引用变量；压缩视图若已经删除该边界，不能用参数名补回。

每份预测必须包含：

- 每个观察量的预期值或方向；
- 停止时点与容差；
- 推导所引用的允许字段或关系；
- 哪些条件会使预测不唯一；
- `indeterminate` 时至少两个兼容结构及其不同预测；
- 熟悉度和污染的阶段更新。

正确猜中结果但没有来自允许材料的有效推导，不构成对 `CA-H03` 的反驳。

## 7. 运行与揭示

全部首次预测冻结后才：

1. 按精确构建、初态和输入运行基线、变体与负对照；
2. 每个构建至少执行两次彼此独立的干净进程调用；
3. 先保存并散列原始输出，再运行派生比较；
4. 使用冻结的比较器和容差，不人工解释结果；
5. 揭示真值、随机映射、别名见证和 `secret_nonce`；
6. 复算承诺；
7. 比较重构、预测、不变量与运行输出；
8. 保存所有失败、异常、补丁和污染声明。

若结果必须依靠主观判断才能分类，说明结果读取方法尚未冻结到可执行程度；该案例返回结论不定，不能由报告作者临时解释成通过。

工程排练可以在正式预测前运行，但只能用于不同输入、非正式配置或构建烟雾测试。若排练已经产生正式配置的精确输出，该输出必须与盲测者隔离，且不能再用于修改任务、预测、比较器或通过标准。

## 8. 熟悉度限制

熟悉度记录任务开始前已有的知识：

- 既往接触本项目；
- 相近类型经验；
- 玩过或研究过相关作品；
- 认出作品或原型；
- 已知精确规则；
- 已知精确变体或结果；
- 无法确定。

熟悉度本身不是违规：

- 认出作品只限制“材料自身足以重构”的证据强度，不自动使提交失效；
- 从允许材料推断作品身份仍属于熟悉度问题；
- 每项必要结构仍须引用允许材料；由记忆补入但材料中不存在的事实不计入恢复；
- 已知精确变体结果的执行者不能为该预测提供独立证据，但其重构阶段仍可按材料单独评价。

若在结果执行或揭示前发现预测者已知精确结果，可以补取一份新的干净提交；原提交永久保留。结果已经产生或揭示后，不得补交到同一轮次，必须开新轮次。

## 9. 完整性污染

完整性污染记录任务开始后发生的禁止暴露：

- 原始来源或明示作品身份；
- 另一种表示视图；
- 预期答案或项目预测；
- 正式结果轨迹；
- 他人提交；
- 包外文件或外部检索；
- 与冻结清单不一致的输入；
- 真值、密钥或随机映射。

逐阶段处理：

| 情况 | 处理 |
| --- | --- |
| 确认看见另一视图、答案、结果或他人提交 | 对应阶段提交 `invalid`，原件保留 |
| 包外访问或外部检索包含必要答案 | 对应阶段提交 `invalid` |
| 只有怀疑且无法查明 | 对应项目 `not_evaluable`，通常使角色结论不定 |
| 单份提交失效，但结果尚未产生、真值未泄漏 | 可以在相同冻结输入下补取一份独立提交，旧件不覆盖 |
| 结果或答案向剩余执行者全局泄漏 | 整轮**轮次无效** |
| 冻结输入、承诺、比较器或首次提交被覆盖 | 整轮**轮次无效** |
| 暴露发生在某阶段提交冻结之后 | 不追溯取消该阶段，只影响后续阶段 |

污染必须记录发生时间、证据、受影响角色、案例和阶段。熟悉度与完整性污染使用不同字段，不能合并成一个笼统的 `downgraded`。

## 11. 四项硬条件的操作化

| 条件 | 通过要求 | 直接失败或反驳 |
| --- | --- | --- |
| `CA-H01` 来源可确定 | 审核 `approved`；版本、构建、输入、时钟、停止边界、容差和待测边界完整 | 必要事实无法由来源确定时，角色结论不定 |
| `CA-H02` 边界可重构 | 两份有效丰富视图提交均 `recovered` 本角色全部不可缺项 | 来源清楚但干净重构仍遗漏、合并或外部补全时，当前表示失败 |
| `CA-H03` 压缩会别名化 | 压缩摘要相同；密封真值含至少两个兼容压缩材料但预测不同的结构见证；压缩组不能从允许材料证明唯一恢复与预测 | 任一有效压缩提交给出可审核的唯一推导，或另一种更紧凑有类型表示无需偷渡即可完成同样任务 |
| `CA-H04` 变体可预测 | 项目事前预测与运行结果匹配；唯一变量成立；不变量全部 `held`；结果可复算 | 隔离关系已经改变但观察量不变、项目预测错误或比较器不能复算 |

此外，两份丰富视图预测都必须 `matched`，才能说 CA-SR 0.1 在本角色中具有独立设计预测力。若项目预测正确而丰富视图预测不稳定，核心边界可能仍真实，但当前表示判为失败。

压缩组输出正确答案不自动使 `CA-H03` 失败。只有它能从允许材料证明唯一性，且审核者确认没有依赖专名、先验答案、自由文本或不透明参数，才构成真正反驳。

## 12. 每个角色的两条结论轴

每个 `CA-R1`–`CA-R3` 分别保存：

```text
compression_claim:
  supported_in_scope
  refuted
  inconclusive

current_representation:
  sufficient_in_scope
  failure
  inconclusive
```

这些是测试报告机器值，不是新**共享术语**。

映射：

| 情况 | 压缩命题 | 当前表示 |
| --- | --- | --- |
| `CA-H01`–`CA-H04` 通过，丰富视图重构与预测均通过 | `supported_in_scope` | `sufficient_in_scope` |
| 压缩视图或更紧凑有类型表示可唯一重构并预测 | `refuted` | 单独判断 |
| 来源与变体成立、压缩确实别名化，但 CA-SR 出现 `representation_gap` 或丰富视图失败 | `supported_in_scope` 或 `inconclusive` | `failure` |
| 来源、变量、轨迹或污染不足 | `inconclusive` | `inconclusive` |

## 13. 组级结论

组级不使用综合分数，保留三角色向量和负对照：

- **范围内通过**：三个核心角色全部满足 `CA-H01`–`CA-H04`；丰富视图均可重构和预测；压缩投影发生别名化；负对照通过；载体与反馈闭环义务完成。
- 核心命题被反驳：任一有效核心角色中，更紧凑的表示无需外部知识即可唯一重构并正确预测。其余角色成功不能挽救冻结的“三角色均须独立通过”主张；报告仍要指出反例只反驳哪一接口。
- **模型失败**：来源与单变量结果成立、压缩确实丢失区别，但 CA-SR 0.1 出现 `representation_gap`，或干净丰富视图不能稳定重构或预测。
- **结论不定**：必要来源未知、变量未隔离、运行不稳定、负对照失败、载体或反馈义务未闭合，或污染影响无法归因。
- **轮次无效**：承诺、冻结字节、派发顺序、比较器或全局隔离被破坏。

优先级：

```text
轮次无效
  > 有效核心反例
  > 当前表示失败
  > 结论不定
  > 范围内通过
```

优先级只避免一份报告同时给出互相冲突的总标题；角色级向量、全部失败和局部支持必须原样保留。

## 14. 跨案例义务怎样结算

### 14.1 行动实现载体

`CA-R2` 的夹具把“版本化脚本执行器 → 定时 `usercmd_t` 命令 → 移动模块”编码为本案的**行动实现载体**。它实际决定哪些方向信号在每个 `8 ms` 子步可被读取，而不是只列键盘或控制器名称。

该记录只适用于项目的确定性程序载体，不声称它代表玩家身体、键盘采样或零售客户端输入路径。若规范编码只从已经形成的 `pm->cmd` 开始，未记录脚本执行器、命令形成和模块读取的关系，则本义务未完成。

### 14.2 效果或反馈到响应机会

`CA-R3` 记录正式结果写回、结果通知、物件进入已判定状态及同一物件再次接受输入的许可关闭：

```text
正式结果提交
→ 已判定状态
→ 同一物件的后续输入机会关闭
```

基线在 `T` 关闭，延迟变体在 `T + 75 ms` 关闭。这里不推断参与者实际会再次按键。

### 14.3 负对照

osu!lazer 的命中动画开关必须只改变绘制或呈现路径。任何正式结果、计分、组合、通知或机制状态差异都会阻止组级通过。

## 15. 行为边界

本轮可以判断：

- 输入是否到达、被识别或取得许可；
- 动作、过程和正式事件的状态；
- 时间、位置、速度与轨迹；
- 结算、效果和系统结果；
- 指定观察者何时取得规则信息；
- 后续响应机会是否开放。

以下一律范围外：

- 更顺手、更难、更公平；
- 玩家会采用什么策略；
- 操作手感、技巧深度和体验；
- 哪个变体更好玩。

如果组级结论依赖这些主张，本轮不能判为**范围内通过**。

## 16. 禁止救援式解释

- 压缩投影失败只支持对冻结压缩方案的结论，不证明所有紧凑表示都会失败。
- 正确猜测但没有允许字段推导，不构成紧凑表示成功。
- 看见结果后不得增加生命周期里程碑、关系、字段或容差。
- 来源未知不能改写成表示缺口；表示缺口不能改写成来源未知。
- 构建失败、浮点噪声和依赖恢复失败不是理论反例。
- 负对照出现机制差异时，不能把差异吸收成 CA-01 的支持。
- 熟悉度要限制结论，但不能伪装成完整性违规。
- 本轮结果不直接产生新**原语**、共享术语或公开理论层级。
