# 0119 分离人工授权与预测后执行许可

- 状态：已接受
- 日期：2026-07-27
- 修订对象：[ADR 0117](0117-freeze-the-formal-run-package-contract.md)、[ADR 0118](0118-separate-formal-pre-gate-artifacts.md)

## 背景

`continuous-001` 的一次人工门发生在正式盲测派发之前，而正式执行必须等四席第二阶段预测全部冻结之后。若把未来的 `prediction_set_digest` 填入人工授权，就只能预填未知值或在预测后回写已签发凭据；两者都会破坏证据顺序。若运行器只检查一个调用方提供的布尔开关、固定短语、任意文件散列或进程环境变量，又不能证明本次轨迹确实属于获准轮次与已冻结预测集合。

## 决策

正式人工授权与正式执行许可分为两个制品：

1. `formal-human-gate-authorization 0.1.0` 在两提交冻结和一次明确人工门之后建立。它绑定冻结根、真值承诺、最终构建准备、夹具锁、投影审核、派发工具以及执行许可的 Schema、物化器和校验器，并只预先授权“完成盲测派发”和“预测冻结后可以执行”。
2. `formal-execution-permit 0.1.0` 在 `p01`—`p04` 四份首次有效预测提交全部冻结后机械派生。它绑定正式人工授权、按固定席位顺序生成的 `prediction-set-preimage.tsv`、该前像的 `prediction_set_digest`、`CA-R1`—`CA-R3` 范围，以及正式夹具执行和正式比较两个操作。

执行许可不需要第二次人工批准，也不进入它所引用的冻结集合。其物化器必须拒绝合成授权、缺席或重席、条件错配、非规范提交／前像、摘要不一致，以及已经存在正式轨迹或结果的状态。R1、R2、R3 的运行器和比较器只接受同一个只读许可校验器；旧的案例专用确认短语、调用方布尔开关和固定明文 permit 全部废止。

执行许可还必须按 `CA-R1`、`CA-R2`、`CA-R3` 的固定顺序绑定 `execution_targets`。每个目标包含正式运行器、正式输入、测试体、比较器、案例专用支持制品与原始轨迹 Schema 的精确路径和 SHA-256。属于运行包的引用必须同时存在于人工授权所绑定的冻结清单中，且路径、散列与 `included_in_frozen_set=true` 三者完全一致；轨迹 Schema 和通用校验器则进入人工授权的合同闭包。运行器和比较器不能把调用方传入的路径或旧的内置散列当作信任根。

每份原始轨迹和每个正式比较器输出都必须直接记录同一个非零 `execution_permit_sha256`、`formal_input_sha256` 与 `prediction_set_digest`。案例专用比较器在解释轨迹语义之前，必须先调用通用原始轨迹校验器；该校验器重新校验许可、选择唯一执行目标、验证案例 Schema，并拒绝未知字段、重复记录、错误顺序、错误配置或任何散列不一致的旧批次／异批轨迹。人工授权、预测前像、执行许可、正式输入、原始轨迹与比较结果因此形成单向散列链，不建立自包含哈希循环。

## 影响

执行许可 Schema、物化器、校验器，以及三案正式运行器、test body 和比较器必须在人工门前进入审核与冻结依据。人工授权 Schema 的 `contract_artifacts` 同时绑定这些实现。合成自检只能在系统临时目录中的无 Git 可弃副本运行，不得复制或执行正式输入、比较器或真实夹具。本决定不授权正式盲测或正式执行，也不增加**共享术语**。
