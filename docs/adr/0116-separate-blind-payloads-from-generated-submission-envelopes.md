# 0116 分离盲测语义回答与机器生成信封

- 状态：已接受
- 日期：2026-07-27
- 来源证据：`rehearsal-004`
- 修订对象：[ADR 0115](0115-freeze-continuous-action-artifacts-rehearsal-and-release.md)

## 背景

`rehearsal-004` 的六项阶段链检查全部通过，但为了得到两条有效链，共保留了八份 Schema 无效提交和三份因后续阶段失效而退出的有效重构。错误同时出现在运行元数据、枚举、嵌套字段、配置寻址、类型化值和必填字段。

最后一份有效预测依赖派发方提供完整候选响应外壳。因此，本轮证明的是“格式受到强约束时证据链能够运行”，而不是“盲测执行者能够可靠地自由手写完整 `role-submission`”。

入选 v02 提交还自填了晚于实际 Git 冻结时间的 `submitted_at`；预测时间甚至晚于确定性执行开始时间。Git 历史仍能证明正确顺序，但盲测者填写的时钟不能继续作为正式时序证据。

## 决策

盲测者的首次原始回答与正式提交信封分成两类制品：

```text
盲测者
→ reconstruction / prediction response payload

保管工具
→ role-submission envelope
→ role-submission 0.1.2
```

盲测者只填写：

- 污染与熟悉度自报；
- 本阶段的重构答案或预测答案。

保管工具负责：

- 从任务包取得 `run_id`、`task_id`、阶段、案例、配置、观察量与输入散列；
- 从保管者提供的 actor 描述取得执行者与会话信息；
- 在收到原始回答后生成 `received_at`；
- 在预测阶段核对同一 actor、同一 session、同一条件与前阶段精确散列；
- 生成不适用的空数组、`first_submission=true` 和完整输入引用；
- 逐值复制语义字段，不推断、不补写、不纠错；
- 把原始 payload、任务、信封、工具与输出 Schema 的精确字节散列绑定到派生提交。

原始 payload 才是不可改写的盲测认知证据；完整 `role-submission` 是可重复生成的机器制品。原始首答若无效，必须原样保留并使该执行者链退出；不得在同一回答上修补后重新包装。

## 新版本

- `blind-response-interface-0.1.0`：重构 payload、预测 payload 与机器信封；
- `task-packet-0.1.1`：增加允许的配置 ID 与装配后输出 Schema；
- `role-submission-0.1.2`：直接绑定原始 payload 和装配来源；
- `build-role-submission.py`：渲染无答案提示的结构模板、捕获信封、确定性装配与只读复核。

原有 0.1.0／0.1.1 文件与既有彩排保持不变。

## 硬约束

1. 模板中的占位符故意不通过 Schema；执行者必须形成自己的语义答案。
2. 装配器只接受首次保存的原始 payload，不修复无效 JSON。
3. 不确定预测必须提供至少两个相容替代；每个主预测和替代都必须恰好覆盖任务声明的全部配置—观察量对。
4. 两次使用同一 payload 与同一信封装配，输出必须逐字节相同。
5. `submitted_at` 取机器信封的 `received_at`，不采用执行者生成的时间。
6. 正式阶段的同一批有效提交仍应在隔离暂存区收齐后一次归档；无效首答另行保留。

## 放行影响

`rehearsal-004` 保持 `procedure_pass`，不回写。它没有解除正式人工门。

新接口必须先通过一次聚焦彩排：

- 全新空白会话；
- 同一执行者完成重构与预测；
- 两阶段原始首答都必须直接有效；
- 两阶段装配都必须逐字节可重复；
- 原始回答、信封、工具、任务、前阶段与派生提交散列闭合。

聚焦彩排通过后，才可以重新评估正式包准备状态。正式盲测仍须取得 CA-07 规定的一次明确人工放行。

## 理论边界

本决定只修订证据捕获接口，不增加**共享术语**，不改变 CA-SR 0.1，也不构成连续行动理论证据。
