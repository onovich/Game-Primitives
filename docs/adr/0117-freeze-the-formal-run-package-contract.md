# 0117 冻结连续行动正式轮次包契约

- 状态：已接受
- 日期：2026-07-27
- 来源证据：`rehearsal-004`、`rehearsal-005` 与正式包缺件审计
- 修订对象：[ADR 0115](0115-freeze-continuous-action-artifacts-rehearsal-and-release.md)、[ADR 0116](0116-separate-blind-payloads-from-generated-submission-envelopes.md)

## 背景

ADR 0116 已把盲测者的原始语义回答与机器生成的完整提交分开，但 CA-07 的旧目录仍只列完整提交。若直接制作 `continuous-001`，原始回答、机器信封、执行者身份和无效首答将没有统一位置。

正式包还存在两个必须在冻结前解决的自引用问题：

1. Git 提交无法在自身内容中预先写入自己的提交散列；
2. 正式盲测会话只有在人工放行后创建，真实 `session_id` 不可能属于门前冻结输入。

`rehearsal-004` 还显示，原始进程输出、调用记录和比较器输出虽然被保存，但没有被执行结果逐项直接绑定。正式报告可以绑定执行结果，却不能依赖报告文字补足这段散列链。

## 决策

### 1. 正式目录

`continuous-001` 使用以下提交结构：

```text
runs/continuous-001/
├── README.md
├── manifest.json
├── source/
├── inputs/
├── fixtures/
├── execution/
├── submissions/
│   ├── actors/
│   ├── raw/
│   ├── envelopes/
│   ├── invalid/
│   └── *.json
├── reveal/
└── reports/
```

`raw/` 保存盲测者首次返回的精确字节；`envelopes/` 保存保管工具捕获的机器信封；目录根部的提交文件是确定性装配结果。三者均追加而不回写。

### 2. 版本固定

正式包固定使用：

- `blind-response-interface 0.1.0`；
- `task-packet 0.1.1`；
- `role-submission 0.1.2`；
- `run-manifest 0.1.1`；
- `execution-artifact 0.1.1`；
- 其余家族继续使用已冻结的 `0.1.0`。

旧版本与既有彩排不回写。

### 3. 两提交冻结协议

门前冻结使用两个连续提交：

1. **冻结锚点提交**：写入全部门前冻结制品；此时 manifest 保持 `preparing`，`freeze_commit=null`；
2. **清单定稿提交**：只更新 manifest，把 `freeze_commit` 写成前一提交散列，状态改为 `frozen`。

`freeze_commit` 的含义是“首次含有全部冻结制品精确字节的 Git 提交”，不是 manifest 自身所在提交。清单定稿提交不得改动冻结集合中的任何文件。人工门同时展示两个提交。

### 4. 执行者计划与真实身份分离

门前冻结：

- 四个执行席位；
- 条件分配；
- 模型、版本与推理配置；
- 空白会话、工具禁令和派发边界。

门后才创建真实会话，并把实际 actor 描述写入 `submissions/actors/`。机器信封绑定该描述的精确内容。真实 `session_id` 不进入门前冻结集合，也不得用占位符冒充。

### 5. 原始执行证据直接绑定

`execution-artifact 0.1.1` 要求：

- 每次执行轨迹直接列出调用记录与原始输出的路径、角色和 SHA-256；
- 执行结果直接列出比较器输出等派生制品；
- 执行结果继续绑定轨迹包，轨迹包继续绑定执行计划与预测集合。

最终报告通过执行结果形成结构化传递闭包，不用自由文本代替散列引用。

## 放行影响

本决定允许制作来源包、来源编码任务、投影视图、夹具、比较器、任务包、密封真值承诺和全包验证器。它不授权：

- 派发正式盲测；
- 创建四个正式盲测会话；
- 运行冻结正式输入；
- 产生正式精确结果；
- 揭示真值。

这些动作仍等待 CA-07 的一次性人工正式派发门。

## 理论边界

本决定只收束研究制品与证据链，不增加**共享术语**，不修改 CA-SR 0.1，也不构成连续行动理论证据。
