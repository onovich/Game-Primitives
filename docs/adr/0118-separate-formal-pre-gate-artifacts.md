# 0118 分离连续行动正式门前制品

- 状态：已接受
- 日期：2026-07-27
- 修订对象：[ADR 0117](0117-freeze-the-formal-run-package-contract.md)

## 背景

ADR 0117 要求冻结夹具锁、中性变体信封、回答模板、正式输入和第二道投影审核，但原版本矩阵只为任务包、执行制品等宽泛家族指定 Schema。把这些门前制品临时塞进既有家族，会混淆“准备了可执行输入”与“已经执行输入”，也会让测试者可见的变体信封继承不必要的来源路径字段。

## 决策

正式包新增五个职责单一的 Schema：`fixture-lock 0.1.0`、`formal-build-readiness 0.1.0`、`variant-envelope 0.1.0`、`response-template 0.1.0` 与 `formal-input-trace 0.1.0`。夹具锁分别绑定来源身份、兼容、观察与唯一规则变体；每类实现必须如实声明为补丁、不适用或仅由配置实现，不能为满足格式而伪造空补丁。三类实际补丁文件不得重叠；仅规则变体允许“仅配置”，并绑定已锁定的正式输入或通用夹具制品，而不把所引用的通用制品伪称为变体补丁。最终构建准备记录必须让三案的基线与变体配置全部通过，绑定构建证据与仓库外输出散列，并明确没有执行正式输入或产生正式结果；历史工具链探针只能作为它所替代的准备证据。变体信封只允许中性 ID、类型化标量、不变量、观测、停止边界与容差，不提供来源路径、条件映射或预期结果；它必须以匿名字段自包含初态、时间基准、完整有序正式输入、中性不变量定义、结构化容差和停止点定义，预测任务逐项复制并校验这些规格。只派发裸 ID，或把来源专用夹具 JSON 直接交给盲测者，都不满足闭包。正式夹具输入仍由独立 `formal-input-trace` 保存，并在人工门前固定为 `not_executed` 与 `withheld`；回答模板独立于真实回答 Schema 接受占位值。

第二道审核使用 `task-packet 0.1.2` 的 `projection_audit_task_packet`，必须检查 `single_variable_isolation`、`invariant_integrity`、`reference_closure`、`stage2_input_closure`、`atomic_projection_equivalence`、`dispatch_symmetry`、`formal_build_readiness_integrity`、投影忠实度、身份泄漏与答案暗示。任务直接绑定机械生成器、投影规范、两份生成视图、最终夹具锁、执行计划和最终构建准备记录；其中投影忠实度与等价闭包必须同时检查生成逻辑和生成输出。规范编码及 rich 视图中的受控变量不能只在案例边界中声明，至少要被一个结构关系或规则角色精确引用；中性正式输入、时间基准和初态／输入字段也必须能从信封连接到 rich 结构。atomic 视图可以按规范删除这些职责边。既有来源审核若没有覆盖这些闭包，不得被解释为已经通过，编码修正后必须重新审核。审核结果再绑定任务及全部任务输入，manifest 最后收束，不建立双向散列。只读的 readiness 校验器可以解析、散列并检查全部门前制品，但不得调用夹具、比较器或正式输入。

## 影响

既有彩排和旧 Schema 不回写。`continuous-001` 只有在三案构建门通过、正式输入仍未执行、第二道审核通过、所有门前引用进入清单并完成两提交冻结后，才可请求一次性人工门。本决定不增加**共享术语**，不修改 CA-SR 0.1，也不授权正式派发或执行。
